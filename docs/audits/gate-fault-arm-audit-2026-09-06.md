# Gate fault-arm audit: which CI gates pass when their input is absent

**Date:** 2026-09-06
**Trigger:** #3933. cc-release-watch emitted `"features": []` for CC 2.1.263 and every consumer read the empty array as "triaged", because an empty array and an untriaged block are byte-identical.
**Question asked of every gate:** if the thing it checks is missing, empty, or at the wrong path, does the gate still exit 0?
**Scope:** every job in ci.yml, plugin-validation.yml, pr-body-lint.yml, visual-style-lint.yml, version-check.yml, release-please-guard.yml, skill-claims-audit.yml, readme-link-audit.yml, memory-staleness.yml, contract-parity.yml, validate-workflows.yml, the PR Playground gate, skill-sync drift, and every test script under tests/manifests, tests/plugins, tests/quality, tests/ci, tests/config plus bin/validate-counts.sh and the scripts those jobs call (68 gates).

## Method

Two arms per gate, both run for real, never reasoned:

- **control arm**: the gate on input where the marker, rows, or file are PRESENT and correct. Expected exit 0.
- **fault arm**: the same gate with the input removed, emptied, or pointed at a missing path. Expected non-zero. A fault arm that exits 0 is a finding: **FAILS OPEN**.

Each probe is a standalone script that builds its own fixture under `$TMPDIR`, runs both arms, and prints one `RESULT gate=<slug> control=<rc> fault=<rc> ...` line. The 65 script-backed probes were authored by five batch agents against a shared brief and re-run by the lane after every fix; the lane also ran three of its own before delegating (run-tests.sh, plugin-validation skill structure, skill-claims audit) and wrote the live-extracting workflow-step test by hand. Every exit code in the table is the value the probe printed. A gate that could not be exercised locally is NOT EXERCISED with the reason, never pass.

Tags: **MEASURED** = the lane or a probe ran it and the number below is what it printed. **CLAIMED** = read from code, not executed (two guards were added to code that cannot run here and are marked so).

Over half the inventory passed on absent input. The shapes, ranked by how often they appeared:

1. **A loop that never iterates reaches the "all N passed" line with N=0** (22 gates). `for f in dir/*`, `find | while read`, `readdirSync(...).forEach`: the counter is only incremented inside the loop, so an empty or mis-rooted directory prints `PASSED: All 0 skills ...` and exits 0. Fix: assert the count before judging it.
2. **A presence guard that turns absence into a skip** (7 gates). `[[ -f x ]] || exit 0`, `[[ -d x ]] || continue`, `if [[ -f ]]` around each version surface. Fix: the surface is mandatory in this repo, so absence is a failure.
3. **A swallowed failure read as an empty result** (4 gates). `$(gh api ... || true)`, `catch { state = 'unknown' }`, an unmatched `git diff` pathspec, `os.environ.get(var, '')`. Fix: distinguish "could not read" from "read nothing".
4. **A `jq | while read` subshell** (2 gates). The failure counter incremented inside the pipe never reaches the parent, so the gate prints `[FAIL]` and exits 0. Neither check could fail at all. Fix: `done < <(jq ...)`, the form the sibling checks already used.
5. **A dead guard** (2 gates). `files=(glob)` without nullglob is never empty; `[[ -d skills ]]` at a path that has not existed since the plugins/ restructure.

Two gates were vacuous at HEAD, not only under a fault: `test-skill-uniqueness.sh` scans zero manifests today (ork declares `skills: "all"` and is skipped) and `plugin-validation.yml` "Validate skill structure" had exited 0 on every run since the root `skills/` directory went away.

## Found along the way (not the audit question)

- `tests/plugins/test-build-drift.sh` section B runs `head -n N dest | diff -q - src`; Apple diff cannot read `-` from a pipe (`Operation not permitted`, rc 2), so on macOS every agent is reported CHANGED and the gate exits 1 locally. Fails closed, so out of scope here; worth its own fix.
- `tests/plugins/test-marketplace-structure.sh` Tests 4 and 5 extract `source` with sed over object-valued sources and capture the literal `git-subdir`, so MISSING_PATHS and MISSING_MANIFESTS are structurally always 0 at HEAD. Test 2 was converted to jq for this exact reason; 4 and 5 were not.
- `tests/plugins/test-cc-discovery-simulation.sh` resolves `agents_dir` under PROJECT_ROOT, not PLUGIN_ROOT, so with no `agents` key in plugin.json it audits src/agents while the plugin ships plugins/ork/agents.
- `version-check.yml` skips every branch with a conventional prefix by design (release-please owns versions). The only non-skip path is a branch named outside that list; the empty-diff hole was the fixable part.
- Agent probes that PASTE a workflow body cannot see a fix to the workflow; the shipped test lifts bodies live by step name. Probes that anchor on line numbers broke the moment the file was edited above them.
- The sandbox denies writes to bare `/tmp`; release-please-guard.yml writes there. The test rewrites `/tmp/` to its scratch dir before running the body.
