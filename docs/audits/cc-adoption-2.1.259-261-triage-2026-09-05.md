# CC adoption triage: 2.1.259 to 2.1.261 (2026-09-05)

Method: hand triage in lane `adopt-cc-259-261`, reading all 170 changelog bullets of 2.1.259, 2.1.260 and 2.1.261 against ork's real surfaces at `origin/main` = `5ccf3bbed` (hook sources and their Stop contracts, agent and skill frontmatter, `src/settings/ork.settings.json`, the headless `claude -p` callers in `.github/workflows` and `tests/evals`, `tests/security/`, `shared/cc-support.json`). The three snapshots in `shared/cc-snapshots/` were written by `scripts/cc-release-watch.mjs` from the upstream CHANGELOG fetched 2026-09-05 via `CC_RELEASE_WATCH_FIXTURE`, because `claude-release-watch` is dispatch-only; the watcher parsed 386 versions and reported the range as STALE (upstream head 3 releases ahead of `latest_known`, threshold 2).

Every VERIFIED claim below names the command or file that established it; everything else is read from the changelog (CLAIMED).

Result over the 42 rows: adopted-in-pr 0, adopted-doc 9, deferred-S 3, watch 1, upside 21, triaged-noop 8.

Unlike 2.1.253 to 2.1.258, this wave is **not** a no-op for ork. Three rows carry most of the weight:

- **2.1.259 makes skill frontmatter `model:` take effect in interactive sessions.** 39 ork skills declare a pin; until this release every one of them was inert interactively. Nothing to change, but the shipped behaviour of ork changes under users who upgrade.
- **2.1.260 makes `Skill(name)` deny rules cover the `<dir>:name` form.** All 106 ork skills are addressed `ork:<name>`, so an operator who wrote `Skill(audit-full)` to deny one was denying nothing. That is a silent permission gap, and it argues for spelling the prefixed form in `configure`.
- **2.1.261 adds `/skill-doctor`**, which measures unused loaded skills and their context cost. ork ships 106 skills in one plugin and has two home-grown approximations of that question (`audit-activation`, `skill-fitness`), neither of which measures context cost.

One row is a latent hazard rather than a live break. 2.1.261 stops auto mode from silently approving a link that packs content into a public diagram renderer's URL. ork has exactly one such call site, `validateMermaidViaAPI` at `src/hooks/src/lib/decision-history.ts:803`, which base64-encodes caller-supplied Mermaid into a `https://mermaid.ink/svg/` fetch. It is dead code (no caller outside its own unit test), so nothing is broken today, and its only error handling is a catch that returns `true`. It is filed as `watch`, not `triaged-noop`, because it is exported and would ship decision text to a third-party host the moment it is wired up.
