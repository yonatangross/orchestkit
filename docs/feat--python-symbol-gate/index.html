2026-07-31 · the gate that could not see Python

The phantom-symbol gate was npm-only

check-import-symbols.mjs exists to catch imports of symbols that were never published. It has caught real ones. It reads .d.ts files, so it had never looked at a single line of Python — and this repo ships Python in mcp-patterns, langgraph, python-backend and testing-llm.

What the blind spot was hiding

mcp 1.28.0  ->  19 files under mcp/server/fastmcp/
mcp 2.0.0   ->   0 files

from mcp.server.fastmcp import FastMCP ships in 7 places and is a hard ImportError on the 2.x that pip install mcp now resolves to. No version gate catches that: a floor is satisfied by any newer release. Only reading the artifact catches it.

How it verifies, with no type declarations to read

1. resolve the version the skill's DECLARED floor permits  (a <2.0.0 bound means newest 1.x)
2. unzip -Z1 the wheel   -> does the MODULE PATH exist?
3. unzip -p that module  -> is the SYMBOL defined or re-exported?

Three wrong versions before the right one

1. Accused submodules

from sqlalchemy import event was flagged. event is a submodule (sqlalchemy/event/__init__.py), not a name in __init__.py. Fixed by checking the filesystem shape before the source text.

2. Then suppressed the real finding

Skipping whenever a sibling-named distribution existed silently waved through the mcp finding, because an unrelated package literally named mcp-server (0.1.4) is published. A false negative is worse than a false positive: nobody looks again.

3. Then guessed names that cannot be guessed

langgraph.store.base ships in langgraph-checkpoint, and langgraph.store.postgres in langgraph-checkpoint-postgres, which langgraph does not declare at all. A namespace module can live in ANY distribution, so absence from the root wheel is not evidence. The unit of judgement became the ROOT: if a dependency also ships <root>/, skip the root entirely. mcp is not a namespace root, so it is still reported.

Both langgraph phantoms are fixed in this PR. The 7 mcp ones are fixed by #3229, and that composition is verified: applying its <2.0.0 bound makes this gate resolve to the newest 1.x and report "Every verified python import resolves". Two independent PRs, one coherent outcome.

Opt-in via ORK_PYTHON_SYMBOLS=1: it downloads wheels, and a network-dependent hard gate is one people learn to ignore. Wired into run-all-tests.sh so the orphaned-test ratchet stays at its baseline of 1.
