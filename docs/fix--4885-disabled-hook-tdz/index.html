The off switch that crashed

Branch fix/4885-disabled-hook-tdz, 2026-10-30, issue #4885. Putting a hook in ~/.claude/hook-overrides.json "disabled" is the documented way to turn it off. With the payload on stdin as a regular file, run-hook.mjs instead exited 1: ReferenceError: Cannot access 'WORKTREE_PATH_EVENTS' before initialization.

1. Step through module evaluation

BEFORE: the file path dispatched in place
NOW: read in place, dispatch in a microtask

Why only the file path. A pipe delivers its payload through a stream event, which can only fire after the module body has finished, so every const exists by then. The file path (added for #4769 so a payload on a file never loses the 100 ms timer race) reads the file synchronously at line 662, while the module is still evaluating, and ran the hook right there. A disabled hook goes straight to emitHookResult, which reads WORKTREE_PATH_EVENTS from line 870. An enabled hook awaits its handler before it emits, so the module finished first and it did not hit this. Line numbers are from main before the fix.

2. The fix and its proof

The read stays synchronous; the dispatch is queued with queueMicrotask. A microtask runs once the module body has finished and still before any timer or stream event, so the #4769 race fix and the stdinClosed guards are unchanged, and every const below the block is covered, not only this one. The new test runs a disabled hook through run-hook.mjs both ways: the file arm failed before the fix with the exact stack from the issue (lines 887, 915, 631) and passes after it; the pipe arm is the control and passes both ways.
