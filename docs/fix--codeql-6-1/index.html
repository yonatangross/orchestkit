Six CodeQL alerts, two fixes

One 401 message printed a secret-adjacent name into public CI logs, and a lab page escaped only half the characters that matter inside an HTML attribute. Both are root fixes: the leak source is deleted, not redacted, and every attribute interpolation now uses one helper.

Alert 406: a name is a disclosure

announce-release.mjs read HQ_API_TOKEN_REFERENCE, an op:// path naming a vault and an item, and printed it on the 401 path. Value scanners never fire on a name, but the name still tells a reader where to aim. The fix removes the variable read and the workflow passthrough entirely; the message now names the repository variable and nothing else.

before

die(`HQ_API_TOKEN was rejected.
  Rotate ${HQ_API_TOKEN_REFERENCE}
  and update the repository
  HQ_API_TOKEN secret.
  Platform response: ${text}`);

after

die("HQ_API_TOKEN was rejected.
  Rotate the platform token named
  by the HQ_API_TOKEN_REFERENCE
  repository variable and update
  the repository HQ_API_TOKEN
  secret.");

A static test in tests/security/ greps every console, summary and output call for the identifier outside the one allowed naming phrase, and fails if it comes back.

Alerts 385 to 389: half an escaper

The lab page ran card values through esc() before dropping them into href, class and aria-label. It covered & < > only, so a quote inside a value could close the attribute early. escapeAttr covers all five attribute-significant characters and is applied at every attribute interpolation.

before

href="${esc(card.diff)}"
aria-label="Diff for ${esc(card.title)}"

after

href="${escapeAttr(card.diff)}"
aria-label="Diff for ${escapeAttr(card.title)}"
esc() output
escapeAttr() output

Probe runs the same two functions the page ships: esc for text nodes, escapeAttr for attributes. A node test in tests/unit runs the helper on a fixed probe string.
