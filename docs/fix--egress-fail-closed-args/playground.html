Fail-closed interpreter argument classification

After a fetcher pipe, the guard walks the interpreter argv left to right. Known value options always take the next token. Known booleans are skipped. A known code flag or a real script path allows the command. Anything else that looks like an option, or a bare stdin program, is denied.

Walk order

  1. Value option: consume the next token, then continue.
  2. Boolean flag: skip it.
  3. Code flag: allow (inline code or module).
  4. Non-option path (not - / /dev/stdin): allow as a script.
  5. Unknown option, lone -, /dev/stdin, or end of args: deny.
