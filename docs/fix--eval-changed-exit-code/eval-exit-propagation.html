An eval outage was reporting as a skill regression.

#3032 taught the single-skill path to exit 2 for "could not measure", so an infrastructure outage would never read as a regression. The --changed fan-out, which is the path CI actually runs, collapsed every non-zero into 1 and threw that distinction away.

What CI saw

Run 30328867969 · skill quickviz · 7 of 7 prompts returned no answer.

Why it matters more than one red check

    

      The harness printed Trigger: INCONCLUSIVE / Quality: INCONCLUSIVE / Overall:
      INCONCLUSIVE and the job still concluded failure. A check that goes
      red on an outage teaches people to ignore red checks, which is the failure mode the exit code was
      introduced to prevent in the first place.
