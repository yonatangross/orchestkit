1. WebMCP: what orank reads

From the methodology JSON at ora.ai/methodology, check webmcp (5 pts): it parses HTML for WebMCP form attributes (toolname, tooldescription) and scans inline scripts and same-origin JS bundles for document.modelContext registrations, treating navigator.modelContext as the deprecated alias.

Before (live layout chunk, fetched 2026-09-27)

...s=r.filter(e=>!n.has(e.name)),i=e.modelContext;
if("function"==typeof i?.registerTool){for(let e of s)
l(`registerTool(${e.name})`,()=>i.registerTool?.(e));

The helper took doc as a parameter, so no bundle carried the text document.modelContext. It appeared only in homepage prose. orank's result: "Declarative WebMCP preview detected (1 form(s)...)".

After (lib/webmcp-tools.ts)

function registerOnDocument(tool) {
  return typeof document.modelContext?.registerTool === "function"
    ? document.modelContext.registerTool(tool)
    : undefined;
}

It reads the global, and the minifier keeps global property access. The navigator fallback and the provideContext last resort from #4107 stay in the same order. A test pins the literal, and a planted control that reintroduces the alias fails it.

One runtime fix comes along with it. Per the spec, registerTool returns a Promise that rejects on a duplicate name, an empty name or description, or an invalid schema. The #4107 guard caught only synchronous throws, so a rejection would have gone unhandled. The guard now also catches the returned promise.

Not confirmed here. orank's exact matcher is not public, so the score change is unverified until the rescan after merge. Separately, the site serves no Chrome origin-trial token, so ordinary Chrome 149 to 156 visitors never get document.modelContext. Registering a token is an account action at the Chrome origin-trials console, left to the operator.
