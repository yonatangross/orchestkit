ork-extras goes back to a pinned stable entry

The stable channel is two entries, ork and ork-extras, pinned to the same tag by scripts/bump-stable-pin.sh. ork-extras tracked main for a while (#5220) because tag v10.12.0 had no plugins/ork-extras. v10.13.0 does, so the pin PR moved it to the tag, and the release-please stamp on $.plugins[2].version left over from the floating period turned the PR red.

What changed

.release-please-config.json no longer stamps $.plugins[2].version in the marketplace; it still bumps the ork-extras plugin.json files and manifest, which ship inside the tag. The marketplace pins ork and ork-extras to v10.13.0 (the change the bot PR carried). tests/schemas/test-alpha-channel.sh and tests/plugins/test-ork-extras-split.py now require ork-extras to be pinned next to ork, and each carries a control: a floating ork-extras is refused, and a stamp replayed onto the pinned entry is refused.
