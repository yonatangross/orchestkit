A quoted string is data. Unless an interpreter runs it.

OrchestKit · network-egress-guard · issue #3122

The egress guard scanned normalizeSingle(raw), which strips quotes but keeps their content, so grep "bash <(curl x)" got hard-BLOCKED — a search pattern that runs nothing. The fix blanks quoted regions except the argument an interpreter executes (eval, -c, -e, -r). Pick a command: green quote = data (blanked), red quote = executed code (scanned).

🔎 What the guard sees

🧱 BEFORE (quote-blind)

🚪 AFTER (governor-aware)

Governors that make a quote executed code: eval "…" · sh/bash -c "…" · python -c "…" · node/perl/ruby -e "…" · php -r "…". Everything else (grep, rg, echo, git commit -m, bash file.sh) treats the quote as opaque data. The DENY tier uses this view; the ASK tier still reads the raw command so it can see quoted URLs for host-allowlist checks.
