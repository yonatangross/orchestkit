Fork model after CC 2.1.232: explicit subagent_type fork

Issue #3726: two skill docs still stated the pre-2.1.232 implicit-only model. One read order, one quiz. 2026-09-10.

What changed in the docs

Before: implicit only

Fork Pattern (CC 2.1.89): agents are fork-eligible when prompts are short, with no custom model and no worktree isolation. CC detects eligibility automatically. That was the whole story.

After: explicit since 2.1.232

Since CC 2.1.232 forking is on by default and subagent_type: "fork" selects it explicitly. A fork subagent inherits the full conversation and prompt cache and always runs on the parent model; other types start fresh. The old eligibility conditions matter only for ordinary Agent() calls.

Fixed in src/skills/explore/rules/exploration-agents.md and src/skills/review-pr/SKILL.md, matching the note chain-patterns/references/fork-pattern.md already carries. Mirrors under plugins/ regenerated with npm run build.
