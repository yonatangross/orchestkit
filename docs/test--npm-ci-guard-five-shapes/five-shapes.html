hooks / npm ci symlink guard

Five findings that were already blocked, and two gaps beside them.

The guard denies npm ci when it would run in a directory whose node_modules is a symlink, because that empties the tree the link points at. Issue #5336 listed five scanner findings (#29, #36, #38, #40, #51) as unproven. Each shape was run through the real guard here and every one is blocked. While doing it, two other shapes slipped through: a function header hid the cd, and a prefix the text does not show never made the guard look for a linked worktree. This branch fixes both.

The two fixes

    
A function header. A segment that starts with f(), f () or function f was read as a command named f, so the cd and the brace group after it were never followed. The header is now stripped before the segment is read.

    
A prefix the text does not show. A --prefix operand that still holds a dollar sign or a backtick after expansion (a positional parameter, a read or for variable, an unquoted substitution) never marked the directory shaky, so the search for a linked worktree under .worktrees did not run. It now does, and the guard asks only when one is reachable.

    
Not a gap: an alias defined on the same line. A non-interactive bash does not expand it there.
