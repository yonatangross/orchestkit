A missing argument is a usage error

The visual-style pre-flight now distinguishes malformed invocations (exit 2) from style violations (exit 1). Explicit empty titles remain allowed.

Before

$ bin/check-pr-visual-style.sh --title
stderr: (empty)
exit: 1

$ bin/check-pr-visual-style.sh --body-file
stderr: (empty)
exit: 1

$ bin/check-pr-visual-style.sh --title "feat: x" --body-file
stderr: (empty)
exit: 1

After

$ bin/check-pr-visual-style.sh --title
stderr: --title requires a value
exit: 2

$ bin/check-pr-visual-style.sh --body-file
stderr: --body-file requires a value
exit: 2

$ bin/check-pr-visual-style.sh --title "feat: x" --body-file
stderr: --body-file requires a value
exit: 2

Valid input stays clean

$ bin/check-pr-visual-style.sh --title "feat: ok"
[OK] PR title clean
Visual-style pre-flight: clean — safe to open the PR.
stderr: (empty)
exit: 0

Regression coverage: tests/integration/test-visual-style-validator.sh, 19 passed, 0 failed. On unchanged main code the three missing-value checks fail.
