MCP CORS headers for browser hosts

The docs MCP server at /api/mcp allowed only Content-Type and Accept across origins. A browser-based MCP host on another origin also sends MCP transport headers, so the browser stopped the request at the preflight. Server-side clients never send a preflight and were not affected.

1. Run a preflight

Pick the config, then the headers the client sends. The browser allows the request only when every sent header is in the allow list.








2. Where the header names come from


MCP spec, Streamable HTTP transport, revision 2026-07-28: MCP-Protocol-Version, Mcp-Method and Mcp-Name are request headers. Mcp-Session-Id and Last-Event-ID belong to revisions 2025-06-18 to 2025-11-25, and this server speaks 2025-06-18, so its clients still send them. Mcp-Session-Id is also exposed, so a client can read it back from the response.
