The envelope that lost its own label.

Claude Code started rejecting hook output with hookSpecificOutput is missing required field hookEventName. The envelope came from OrchestKit's own output guard — the component whose entire job is keeping malformed envelopes off stdout.

The two-line bug

stdin delivered 0 bytes in 100ms (the #3415 watchdog race)
        │
        ▼
hook_event = 'unknown'          ← normalizeInput's fallback
        │
        ▼
default-timeout-setter emits    hookSpecificOutput: { hookEventName:'PreToolUse',
                                updatedInput:{ command:'', timeout:120000 } }
        │
        ▼
output-guard Rule 1: 'unknown' is not allow-listed
        └── delete hookEventName  ← but keep everything else
        │
        ▼
{"hookSpecificOutput":{"updatedInput":{"command":"","timeout":120000}}}
        │
        ▼
CC: "hookSpecificOutput is missing required field hookEventName"

Why the strip was worse than the bug it guarded

Every key inside hookSpecificOutput is event-scoped

updatedInput, permissionDecision, worktreePath — none mean anything without the event label that tells CC how to read them. Deleting only the label left a body CC could not place: guaranteed to fail validation, every time. The honest move on an event that cannot consume the object is to drop the object, not to remove its name and keep the rest.

The regression that refined the fix

Dropping wholesale on unknown fixed production but broke the security suite (expected deny, got abstain). The cause: the harness fires hooks with real commands and no hook_event_name — so unknown was conflating two very different situations.

payloadmeaningruling
empty ({})watchdog / stdin error — hook measured nothingdrop the envelope: a verdict on no input is noise
real, no event fieldprobes, test harness — the hook did real worktrust the declared hookEventName; CC routes on it
known non-consumere.g. WorktreeCreate carrying a PreToolUse labeldrop the whole object (#1794)
consuming, namelesshand-rolled envelope missing the fieldinject the firing event

What changed

output-guard.mjs — the boundary

An emptyPayload flag flows from normalizeInput through emitHookResult: on an empty payload the envelope is dropped before any other rule. On unidentifiable events a self-describing envelope now survives; a garbage-labeled or nameless one still dies at the final invariant. Three pretool/bash emitters that hand-rolled bare envelopes carry hookEventName at the source.

The invariant, stated once

∀ result leaving the guard:
  result.hookSpecificOutput ≠ undefined
    ⇒ result.hookSpecificOutput.hookEventName ∈ EVENTS_WITH_HOOK_EVENT_NAME

Forty-one contract tests pin it across every known event plus unknown and ''; the byte-exact production repro (empty stdin → timeout-setter) now emits {"continue":true,"suppressOutput":true} and nothing else.

Refs: the CC validation error reported in super-conductor-33; the #3415 stdin watchdog that makes empty payloads possible; #1794, the mismatched-label incident this guard was built for; and the security-suite abstain regression that split 'unknown' into its two honest meanings.
