Signed skill-autoheal commits

Skill Build Autoheal regenerates committed build output on a PR that only edited src/. It used to build the commit on the runner and push it, which left an unsigned commit on the PR branch (#5012). It now creates the commit through the GitHub API, which GitHub signs.

Before

  • Runner runs git commit as github-actions[bot]
  • Pushes it with the App token
  • Commit signature: none (unverified)
  • Security review legs flag it; removing it needs a force-push

After

  • Runner stages the gated paths and reads the staged diff
  • scripts/ci/api-commit.mjs uploads blobs, builds the tree, creates the commit with no author set
  • GitHub signs it: verification.verified = true
  • Branch moves fast-forward only, and only if the commit came back verified

Two jobs, one token

  • build runs the PR's npm ci and build with no secret, and uploads only a patch of the gated paths.
  • autoheal mints the App token and runs no PR code: it checks the PR head out as data, applies the patch, and runs api-commit.mjs from the base commit with --strict (any change outside the gated paths stops it).
  • A build step can no longer reach the token through GITHUB_ENV, NODE_OPTIONS or a background process: those do not cross a job boundary.
  • No checkout persists a credential. GITHUB_TOKEN stays contents: read; the App token keeps contents: write only, as before.

Tests

tests/ci/test-skill-autobuild-api-commit.mjs runs the script against a fake GitHub API: drift with an edit, a new file, a deletion and an exec-bit change; an unverified commit; a tree mismatch; no drift; branch names with #, ?, % and a nested a/b; a misrouted GET or PATCH answer; a branch that moved since the build; and --strict. It also fails if the workflow pushes from the runner or puts the token in the job that runs PR code.
