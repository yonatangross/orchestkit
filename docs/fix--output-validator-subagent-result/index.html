The Validator That Read an Absent Field

The first hook in the SubagentStop sync pipeline validated a field the caller does not send. Claude Code 2.1.272 delivers the subagent result as last_assistant_message (GH-4158) and carries neither agent_output nor output (0 of 11,319 captured rows, #3034), so every check in output-validator.ts ran against an empty string while the real result sat one reader call away.

The one line

before: const rawOutput = input.agent_output ?? input.output; read a field that is never present on a real payload.
after: const output = getSubagentResult(input); reads through the shared reader (GH-4158, PR #4168), which prefers last_assistant_message and falls back to the legacy names.

The #3200 defense survives unchanged: an absent result is never an error, because reporting one as an ERROR once starved the hooks behind this one for two months. The reader skips empty strings, so "delivered" now means a non-empty result in any supported field.

Measure it yourself

Send the hook the measured 2.1.272 payload shape. Only the result field differs between the two lines.

old line: agent_output absent, output absent → output length 0, checks vacuous

Mutation check: reverting the one line to the old read makes T1 fail with "Errors: Agent produced empty output", the exact #3200 shape. Restored, the subagent-stop suite is 440 of 440 and the full hooks suite is 6716 passed, 2 skipped.
