ork tool dispatchers become the shipped default

Branch feat/ork-dispatch-default-on. scripts/build-plugins.sh now writes plugins/ork/hooks/hooks.json as shippedToolHooks(src/hooks/hooks.json) (#4962, #4971): one PreToolUse and one PostToolUse dispatcher, every other event kept, PostToolBatch included. Only the opt-in flag variant (unifiedToolHooks) drops PostToolBatch. src/hooks/hooks.json stays the per-handler registry. Numbers below are a replay by scripts/measure-hook-processes.mjs on 2026-11-02 against the flag variant (PostToolBatch dropped), three runs in alternating order at load 23 to 26; they are local wall clock, not production. The shipped default adds one async tool-batch-observer process per batch on top of them, not measured here.

Why the wait does not grow. Before, most PostToolUse observers were async: Claude Code did not wait for them, but each was still a node process. Now they run inside the one PostToolUse dispatcher, after the guards and within their own budgets, so their time counts toward the wait. The median wait still fell for every tool, because one process start replaces several.
