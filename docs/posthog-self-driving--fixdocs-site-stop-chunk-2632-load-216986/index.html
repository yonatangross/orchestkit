A missing Lab page serves static HTML, not the app

Branch posthog-self-driving/fixdocs-site-stop-chunk-2632-load-216986. A PR body links its playground at https://orchestkit.dev/lab/<slug>.html, and CI requires that link. The URL is live only after the PR merges and deploys. Before that, Next.js served its full not-found page under the /lab CSP. That page hydrates the client bundle and loads the search client (chunk 2632), and PostHog recorded Loading chunk 2632 failed on those visits. New: app/lab/[...slug]/route.ts answers any /lab/* path with no file behind it with a static, script-free 404.

Why public files still win. Next.js checks the filesystem (public/) before dynamic routes, so a published playground never reaches the new handler. The local production build confirmed it: a published page answered 200 with its own HTML, a missing one answered the new 404.
