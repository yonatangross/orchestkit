OrchestKit · .github/workflows/ci.yml

A required gate asked a first-time contributor for an interactive playground, to add a badge.

The PR Playground check skips bots and branches named dependabot/, ci/ and friends. An outside contributor has no such prefix, so a one-line README.md diff was told to ship a hand-authored HTML playground. Being a required check, there was no way through.

Two bugs found while writing the fix

    
Both were caught by tooling rather than review, and both were in code about to ship.

    

      

        fail-open race
        
grep -q in a pipe under pipefail

        

          The first draft piped into grep -qvE.
          grep -q exits on the first match, the producer takes SIGPIPE (141),
          pipefail propagates it, and the enclosing
          if flips non-deterministically under load.
        

        

          In a required gate that races fail-open: a user-facing PR would sometimes be
          waved through with no playground. Fixed with a here-string, which has no producer process to
          signal. Caught by the repo's own silent-failure hook.
        

      

      

        would have re-blocked
        
Anchor applied to the whole alternation

        

          ^(…|\.github/|…)$ anchors the trailing $
          against every branch, so \.github/ only matched a file literally
          named .github/.
        

        

          Every real workflow path fell through to "playground required" — the exact class of bug the fix
          exists to remove. Caught by the new test, not by reading the regex.
        

      

    

  


  

    Make the PR Playground gate decide from the changed files instead of the branch name, so docs-only contributions from outside contributors are exempt, keep it fail-closed for unknown paths, and collapse the duplicated skip logic into one step.
