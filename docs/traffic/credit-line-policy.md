# Credit Line Policy

Status: DRAFT. Nothing in this file has been posted, sent, or submitted anywhere by anyone. Publishing or sending anything that uses these lines requires the operator's explicit word. X (Twitter) is read-only for this workstream: reading is in scope, posting is not.

## Why exactly one wording per line

Credit lines are attribution anchors. When the kit or one of its public skills is mentioned externally, the mention carries the same line, word for word, every time. Consistent anchors keep attribution in referrer data clean, concentrate search signals on one URL, and stop improvised variants from drifting apart. There is exactly one kit-level line and exactly one line per public skill. Do not reword, do not shorten except to the approved short form, do not substitute a different URL.

## The kit credit line (exact wording)

When mentioning the kit as a whole:

> OrchestKit is a Claude Code plugin: reusable skills, specialist agents, and lifecycle hooks, packaged as one installable plugin. https://github.com/yonatangross/orchestkit

Approved short form, for space-constrained surfaces only:

> OrchestKit (Claude Code plugin): https://github.com/yonatangross/orchestkit

Rules:

1. One credit line per mention artifact (a post, a list entry, an issue, a PR description), not per paragraph.
2. A draft that names a specific public skill carries that skill's exact line from the table below; adding the kit line as well is allowed but not required.
3. A draft that names no specific skill carries the kit line.
4. The URL is always `https://github.com/yonatangross/orchestkit`, exactly as written.
5. Never attach numbers (stars, installs, users) to a credit line: numbers age, and drafts must not claim unverified figures.
