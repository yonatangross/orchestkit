Seven AbortErrors that came from a card entrance

GH-4155: the docs site CI job was green on 763 tests and still failed the step, because vitest exited nonzero on seven unhandled rejections of AbortError: The animation was canceled. This page replays the mechanism and the fix.

The mechanism, in one paragraph

PR #4153 made each host card start its entrance from a post-mount animate (a mounted state set in useEffect), so the static HTML never bakes in invisible cards. In a browser that is a spring entrance. In the vitest run the environment is happy-dom, whose Element.animate is real enough that motion-dom starts actual Web Animations: seven cards, 500 ms each, staggered by 50 ms. When the test ends, @testing-library unmounts the tree, motion cancels the animations mid-flight, and each cancelled Animation.finished promise rejects. Nobody in the component awaits that promise, so the rejection surfaces as unhandled and vitest counts it in an Errors line that gates the job. It is timing dependent: the same job was green on the PR head, because whether a cancel lands mid-flight depends on how long each test takes.

The fix, test side only

The component is untouched. docs/site/__tests__/host-install-picker.test.tsx installs a matchMedia stub in beforeEach that reports reduce, except for the one test that exists to assert reduced-motion rendering and keeps its own explicit stub. Placement matters: motion initializes a module-global ref from matchMedia on the first useReducedMotion() call and never re-reads it, so the stub has to be in place before the first render of the file, which is exactly what beforeEach guarantees.

+function reducedMotionMatchMedia(query: string) {
+  return {
+    matches: query.includes("reduce"),
+    media: query,
+    onchange: null,
+    addEventListener: vi.fn(),
+    removeEventListener: vi.fn(),
+    addListener: vi.fn(),
+    removeListener: vi.fn(),
+    dispatchEvent: vi.fn(),
+  } as unknown as MediaQueryList;
+}
 describe("HostInstallPicker", () => {
   beforeEach(() => {
     search = new URLSearchParams();
     replace.mockClear();
     vi.mocked(track).mockClear();
+    vi
+      .spyOn(window, "matchMedia")
+      .mockImplementation(reducedMotionMatchMedia);
   });

Cleanup was already covered: docs/site/__tests__/setup.ts registers an explicit afterEach(cleanup), so the tree unmounts before the next test and no extra hook was needed.

Why not fix the component

Awaiting the finished promises inside host-install.tsx, or gating the entrance on a test-only flag, would put test plumbing into a shipping component for an artifact that only exists under a simulated environment. Reduced motion is a real user preference the component already honors; telling the test environment to report it keeps the simulation honest and the diff inside __tests__.
