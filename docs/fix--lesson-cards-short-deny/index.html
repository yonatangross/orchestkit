A stopped call is one line, not a red wall

When a block lesson stops a command (Cancel, Escape, no answer), Claude Code draws the refusal as a red tool error. The refusal used to repeat the whole lesson and its multi-line fix, so the pane showed the same text twice: once in the card, then again as a red wall. Now the refusal is one short line with the lesson id, its first sentence and a short fix (the model reads only this line on a refused call, so it still learns the alternative); the card above keeps the full lesson.

Before

Error: lesson-cards: no explicit "Proceed anyway" came back at lesson git-ls-files-quotepath-blind, so this call did not run.
[lesson:git-ls-files-quotepath-blind] A "not tracked" read from `git ls-files` is blind to non-ASCII paths. ...
  (about 15 more red lines: the full lesson and every fix example)

After

Error: lesson-cards: no explicit "Proceed anyway" came back; call not run. [lesson:git-ls-files-quotepath-blind] A "not tracked" read from `git ls-files` is blind to non-ASCII paths. Fix: git ls-files -z | tr '\0' '\n' | grep -qxF "$name"

One line, at most 240 characters. Tests pin the shape: no newline, at most 240 characters cut by whole characters, the id, the first sentence and a short fix present, never the multi-line fix block.
