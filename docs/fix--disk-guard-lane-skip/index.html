disk-cleanup / Private lane guard

What the disk guard skips and what it still cleans

A plugin can list private lanes in configs/private-lanes.json. disk_cleanup.py never sizes, walks or deletes inside a lane, and it prints a find command that leaves the lane out too. Everything else is handled as before.

Fixture cases from tests/skills/integration/python/test_disk_cleanup.py, run on macOS
PathWhat it isOutcome
~/lanes/example-lane/A lane folderSkipped: not sized, not searched for repos, not cleared
~/.npm/_cacache/nested/lane/A lane two levels under a cache that gets clearedSkipped: --apply empties around it and never removes its parent whole
~/.claude/projects/<lane slug>-repo/Sessions started in a lane subfolder or worktreeSkipped: a sibling slug dir with a dash after the lane slug counts as the lane
~/.claude/projects/other/Old sessions from an ordinary folderStill listed, and the printed find deletes files older than 30 days
~/.npm/_cacache/nested/other/A cache folder next to a nested laneStill cleared by --apply
~/.claude/projects/<lane slug>x/A folder that only shares the first lettersNot a lane, so handled as an ordinary folder

If a lane list is present but unreadable, not valid JSON, not a list, or holds a blank or non-string entry, the run refuses with exit 2 before it sizes or deletes anything. With no list installed there are no lanes and nothing changes.

Run the checks 
python -m pytest tests/skills/integration/python/test_disk_cleanup.py

The command tests run the generated find on a fixture home, so the lane files are checked on disk, not in the printed text. Only macOS find was run.
