Three hook texts that no longer reach the model by default

Branch feat/hook-text-cuts. Each of these hooks used to put text in the model's context on its own. Now the first is opt-in, the second keeps only structured errors, and the third goes to the person instead of the model. The text in each pane is the text the code in this branch produces; the character counts in section 1 are counted from it.

1 / Visual-style reminder: off until you turn it on

The reminder carried one person's chat style (render size, icon set, a skill name) as default text on every prompt that asked for a shaped answer. It is now silent unless ORK_VISUAL_STYLE_NUDGE=1. With it on, the text is your own file (ORK_VISUAL_STYLE_NUDGE_FILE, first 1500 characters), or one neutral line.

Before: injected by default

After: ORK_VISUAL_STYLE_NUDGE=1, no file

With the variable unset, nothing is injected.

2 / Failure tips: structured errors only

The generic tips table matched any failure whose text contained a common word. lock matches blocked, so a pane that refused input because a dialog was open was told "Resource is locked". The table is gone; structured errors (RFC 9457 payloads with their own title and retry guidance) still get their block.

Before: injected into the model's context

After

3 / Version notice: to the person, not the model

A newer Claude Code than the feature matrix knows is news for the person. It used to arrive as session-start context written as an instruction to the model. It is now a message to the person only. The hook also runs synchronously now: an async hook's message is delivered to the model on the next turn and is not shown to the person.

Before: additionalContext (model)

After: systemMessage (person)
