CI playground: fix/rp-heavy-skip

Which PRs skip the heavy suites, now that the gate fails closed?

This PR replaces the release-please gate from #5470 with a fail-closed design. A skip needs four facts to agree: a release-please--* head branch, the repository's own release bot as PR author, every listed commit authored by that bot, and every changed path on the release-owned allowlist. Anything else runs the suites; and if the gate job itself fails or is cancelled, every consumer's if: still evaluates (!cancelled() plus a needs.rp-gate.result check) so the suites run and CI Summary turns red instead of skipping green.

Event data

Fail closed means failure looks like failure

The first gate answered one question: may we skip? This one answers a harder one: may we skip safely. The consumer condition is !cancelled() && !(needs.rp-gate.result == 'success' && needs.rp-gate.outputs.skip == 'true'), so a gate that crashed, timed out or was cancelled leaves the suites running rather than exempting them. CI Summary needs the gate and fails on any non-success result, so a gate that could not decide can never read as a green checkmark. The commits check closes the last hole: a human push onto a release-please--* branch used to inherit the skip through paths alone. A changed-file or commits list that does not match the counts the pull object reports, a rename whose old path escapes the allowlist, and a branch that moved mid-read all keep the suites running too. tests/ci/test-rp-diff-gate.sh and tests/ci/test-rp-gate-wiring.sh cover every arm red first.

Source of truth for the demo: scripts/ci/rp-diff-gate-allowlist.txt and scripts/ci/rp-diff-gate-decision.sh on this branch.
