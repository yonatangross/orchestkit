Four defects: one producer, three floors, and an archive nobody capped

Interactive companion to fix/producer-and-stale-floor. Everything below is measured, not modelled.

A. The producer that squares your token count

Claude Code re-reads the whole cached context every turn. A turn's cache_read_input_tokens is therefore a re-read of context already counted once under cache_creation. Summing it per turn re-counts the same context once per turn, so total_tokens grows with the square of the turn count.

The server-side parser was fixed on 2026-07-14. The producer was not, and on prod the producer is the only path that runs: the API cannot read a laptop transcript_path.

Try it

Context is modelled as growing by the per-turn unique volume, so turn N re-reads about N times that volume. Inflation is independent of the per-turn value: it is 1 + (N+1)/2, which is why long sessions blow up and short ones look fine.

C. The 300 MB file that #3151 did not cap

#3151 bounded the ACTIVE file at 10 MB. Measured right after it landed: 

hook-timing.jsonl            236 KB   <- the file #3151 capped
hook-timing.2026-07.jsonl    300 MB   <- where 99% of the bytes actually are

Rotation without retention just moves unbounded growth one filename over. The same two copies also shared a latent data-loss bug: the archive name is derived from the current month, so a second rotation in the same month resolved to the same path and renameSync silently destroyed the first archive.

before unbounded

active  > 10 MB ?
   |
   +-- rename -> name.2026-07.jsonl
                   |
                   +-- (nothing)

second rotation, same month:
   rename -> name.2026-07.jsonl
             ^ overwrites, no error

after bounded

active  > 10 MB ?
   |
   +-- pick a FREE name
   |     name.2026-07.jsonl
   |     name.2026-07.2.jsonl
   |     name.2026-07.3.jsonl  ...
   |
   +-- prune oldest by mtime while
         count > 3  OR  total > 50 MB
       (never below 1 archive)

Steady state is about 30 MB per analytics base name instead of unbounded. The existing 300 MB archive is pruned by the code on the next rotation once newer archives exist; this PR does not delete anything itself.

One implementation, not two

bin/run-hook.mjs and src/lib/analytics.ts each carried their own copy, and both carried both defects. They now import bin/analytics-rotate.mjs: plain ESM with no side effects, so the dispatcher can load it at runtime and the esbuild bundles can inline it at build time.

D. Tests for a helper that shipped with none

#3151's commit message claimed "Verified: 7 direct assertions on the helper". git grep rotateAnalyticsIfNeeded matched no test file. There were zero.

The 15 new tests run against a real temp directory rather than a mocked node:fs. Both defects are filesystem-state defects (which file exists, how many, how large, which one got deleted), and a call-shape assertion on a renameSync mock is exactly what let them ship.
