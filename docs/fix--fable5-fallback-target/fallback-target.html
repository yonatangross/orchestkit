The Fable 5 guide named the wrong fallback model

PR #3206 · fix/fable5-fallback-target · two occurrences, one visible on the rendered page

The correction

The guide said Fable 5's safety classifier falls back to Opus 4.8. That was accurate when Fable 5 shipped on 2026-06-09, because 4.8 was the current Opus. Opus 5 has since shipped, so the sentence became wrong without anyone editing it.

line 8 · intro paragraph (NOT visible in the section a reader lands on)

line 42 · "Fallback behavior to know about" (this is the one on screen)

Why fixing only the visible one would have been wrong. The rendered page surfaces the line-42 section. A reader reporting the bug sees that sentence and nothing else. Patching just it leaves the intro paragraph asserting the same stale fact three screens higher up.

What was deliberately NOT changed

It bills at $10 input / $50 output per MTok
  — 2x Opus 4.8 output pricing —          <-- LEFT ALONE
  and in under 5% of sessions a safety classifier
  transparently falls back to Opus 5       <-- FIXED

Both phrases say "Opus 4.8" and sit in the same sentence, but they are different claims. One is the fallback target. The other is a relative-pricing baseline. Re-baselining the pricing comparison needs actual Opus 5 pricing, which a find-and-replace does not supply. Flagged as a follow-up rather than guessed.

The reusable check. Before editing anything under a docs tree, ask whether a generator owns it. Reference pages under docs/site/content/docs/reference/ are generator-owned; hand-written guides under docs/site/content/docs/guides/ are not. Getting it backwards fails CI in a way that looks like infrastructure breakage rather than a layering mistake.

Why this class of rot is hard to catch

  • Nothing was edited. The sentence was true when written and decayed in place as the model lineup moved.
  • No test asserts it. There is no gate comparing prose model names against a canonical list, and shared/cc-support.json carries no fable entry to compare against.
  • The page renders perfectly. Fact rot has no visual signal, which is why it took a human reading the rendered page to spot it.
