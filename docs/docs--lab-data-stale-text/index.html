No Conflict Left to Resolve

PR 4188 made the Lab aggregate a generated file. Two contributor docs kept the old advice anyway: they told people to take either side when lab-data.ts conflicts. This change deletes that advice, because the file it names can no longer be in a conflict at all.

The two passages

The pull request template and the create-pr skill both carried a version of the same sentence. The generated reference mdx and the plugins copies are rebuilt from the skill source by the root build, so the fix is two hand edits and one regeneration.

before: On a merge conflict in the generated lab-data.ts, take either side and rebuild; never hand-resolve it.
after: The lab-data.ts aggregate is generated at build, dev and test time and is not committed, so there is no conflict to resolve on it: publish a playground with one fragment under docs/site/lab-manifest/ and rebuild.
Why the old advice broke

A committed file can conflict. A generated one cannot: it is not in the index, so a merge never sees it. Try the merge that used to be the scary case.

old world: lab-data.ts tracked, both PRs edit it → conflict expected

The fix touches docs only: one template, one skill source, and the bytes the build derives from them. No runtime behavior changes.
