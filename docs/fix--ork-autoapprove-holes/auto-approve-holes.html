What the opt-in auto-approve hooks no longer approve

With ORK_PERMISSION_AUTO_APPROVE=1, the safe-bash, project-writes and learning-tracker hooks approved requests that run code: a git option that launches a program, a package script by any name, a write to a file a later test run executes. They now drop those to the normal prompt. Ordinary reads and test runs still pass.

How the checks work now

  • git options that run a program, write a file or point at another repository (-c, -C, --upload-pack, --output, --ext-diff, --git-dir and more) are rejected in full and in every abbreviated spelling, because git accepts any unambiguous prefix of a long option. So are git grep -O / --open-files-in-pager and a top-level -p / --paginate; git log -p stays allowed.
  • Globs, brace and tilde-user expansion, $ and backticks outside single quotes, and a trailing & refuse auto-approval: an argument the hook cannot read literally cannot be checked against the credential-path list.
  • Quote stripping is one scanner that tracks which quote it is in, so an apostrophe inside a double-quoted string no longer hides live shell syntax.
  • The write denylist runs on the requested path and on the symlink target, and now covers files whose content later runs as code: package.json, pyproject.toml, Makefile, conftest.py, shell rc files, .vscode/, .idea/, plus CLAUDE.md and AGENTS.md.
  • A learned prefix must end on a word boundary, and learned approvals never override the shared reject list.

Not covered

  • Auto-approved project writes plus an auto-approved test run is still code execution by design: a written test file runs under pytest or npm test. The denylist keeps writes away from tool config and agent instructions; it does not make the flag safe for untrusted input.
  • npm audit still matches npm audit fix, which installs packages. It was approved before this change too.
