Both op:// segments must now be placeholders

Issue #4224. tests/security/test-public-surface-names.sh greps tracked files for op://vault/item paths. The old rule skipped a hit when either segment read as a placeholder, so a <vault> vault could hide a real item name even though the name itself is a disclosure. The guard now requires the vault segment to be placeholder-shaped and the item segment to be placeholder-shaped or one of the documented generic words (Item, name, credential, key, secret, password, token, entry, login).

Try it

Type an op:// path; the classifier applies the new rule.

pathverdict

What had to change in the tree

Real item names were riding behind placeholder vaults in tracked files. They were genericized to <item>/<field> at the source and regenerated: the configure skill's MCP reference (src, plugins, docs-site mdx), the .claude/templates/mcp-*.json Tavily examples, packages/hook-contract-py/RELEASING.md (PyPI item), src/hooks/README.md (orchestkit item) and one hook test fixture. A literal placeholder vault could not previously reach the item check at all because < was excluded from segment characters; the segment class now admits angle brackets. The word list is exact-match, so a real item that merely starts with a listed word fails too. The negative case (placeholder vault, real-shaped item) is proven by a must-fail fixture inside the guard script itself: it feeds five real-name paths through the same grep+awk pipeline and asserts all five are flagged.
