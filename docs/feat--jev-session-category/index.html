ORCHESTKIT LAB · FEAT--JEV-SESSION-CATEGORY

Session Category as a Typed Choice, in Shadow

Every session spawns a detached claude -p --model haiku process to name it and pick one of eight work categories, which becomes the session color. This PR adds an opt-in shadow: the same category question asked as one typed Choice to TypeSafe's Jev model. Nothing you see changes. Haiku still decides the title and the color; the Jev answer is only stored beside it.

What runs, and when

turn 1 ─┬─ haiku claude -p (unchanged) → session-identity.raw → title + color └─ Jev Choice (only if opted in) → session-identity.jev.json turn N ── both known → session-identity.shadow.json + one hook log line (labels, confidence, latency, tokens; never prompt text)
SettingBehavior
nothing set (default)haiku only, no network call, no new files
ORK_SESSION_CATEGORY_PROVIDER=jev onlystill haiku only (no key, no call)
provider jev plus the TypeSafe key variable ORK_TYPESAFE_API_KEYhaiku as before, plus one Choice call with a 1.5 s abort; the pair is logged

What leaves the machine when opted in: the branch name and the first 600 characters of the first prompt, sent to a third-party processor. Model pinned to jev-1.13.0, because jev-latest moves.

One category set, enforced

The eight category descriptions now live in one map, CATEGORY_DESCRIPTIONS. The haiku prompt sentence and the Choice criteria are both generated from it. Contract tests pin that the Choice keys equal WORK_CATEGORIES in order, that no other option was added, and that the haiku sentence is byte-identical to the text before this PR.

Kill criterion (fixed before the run): stop if Jev's agreement with the hand labels is more than 5 points below haiku's, or its p95 latency is above 1,000 ms.
