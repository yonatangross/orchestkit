A skill card and an install picker in the OrchestKit chat display

The docs MCP at orchestkit.dev/api/mcp had one inline view, the search results. It now has two more, each bound to a new read-only tool. The cards below are the exact views the server serves, filled with what the tools return.

01 / Skill card: orchestkit_skill_get

Input: a skill name. The card shows what it does and which plugin ships it, both read from the generated skills data, and the install line with a copy button. A name that does not exist gets a "No such skill" card with the nearest names, never an empty frame.

02 / Install picker: orchestkit_install

Pick Claude Code, Cursor or Codex. The exact command for that host appears with a copy button. The pick happens inside the frame, with no network call. The commands come from the same list the home page and the install docs use, and a test checks each against the repo's manifests.

03 / What every view promises

  • No external script, font or image, and connect-src 'none': the frame makes no request.
  • Native buttons and radio inputs, a visible focus ring, text at 4.5:1 or better, light and dark, laid out for 390 px.
  • Text is written as text, so a skill description cannot inject markup.
  • Bound the same way as the search card: _meta.ui.resourceUri and openai/outputTemplate.
