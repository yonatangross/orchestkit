auto-lint runs only the formatters a repo configures

Branch fix/4945-auto-lint-config-gate, 2026-10-30, issue #4945. The PostToolUse hook posttool/auto-lint ran a formatter over the whole edited file after every Write or Edit, whether or not the repo uses that formatter. Measured on 2026-10-28: a few-line test edit became a 260 insertion, 155 deletion diff.

1. Pick a file and the repo's configs

Assumes ruff, biome and prettier are all installed, the common case on a dev machine.

BEFORE: whatever is installed runs
NOW: only what the repo configures

The rule. A config counts when it sits in the edited file's directory or any parent up to the project root. A pyproject.toml counts for ruff only with a [tool.ruff] table; a package.json counts for prettier only with a "prettier" key. ruff check --fix can delete code it calls unused (side-effect imports), so it also needs ORK_AUTO_LINT_FIX=1. SKIP_AUTO_LINT=1 still turns the hook off.

2. What is not in this change

Formatting only the changed lines (ruff and prettier both have range options) was the issue's first choice. The hook gets the edit as old_string and new_string, not as line numbers, so a range has to be derived; that is left for a follow-up, and this PR takes the second choice: a formatter the repo has not chosen never runs. Red tests: 5 cases failed before the fix and pass after it, plus 2 controls that pass both ways.
