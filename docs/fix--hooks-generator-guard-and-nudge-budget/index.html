hooks.json generator fails closed; SDLC nudge gets a time budget

Branch fix/hooks-generator-guard-and-nudge-budget. Fixes #5004, refs #5006. Two small hardening fixes in the hook build and the Bash advisory path. The traces below are a model of the code paths, not measured runs; the tests named in each note are the evidence.

1. How is the generator invoked?

before (main)

after (this PR)

Why it was silent. The main-module check compared process.argv[1] (the path as typed) with import.meta.url (the real path). Through a symlink they differ, so the CLI block never ran and node exited 0. invokedAsScript now compares real paths; the same fix lands in check-dispatch-proof, measure-hook-processes and spawn-ratchet. build-plugins.sh deletes the copied per-handler file first and fails if the generator leaves nothing. Pinned by unified-pretool-hooks-symlink.test.ts (4 of its 5 tests fail on main).

2. How slow is the skills folder?

What the budget does not cover. readRepoSkills runs inside the sync Bash advisory dispatcher. It now reads at most 40 folders and stops reading once 50 ms have passed (the clock is checked between reads, so one read can overrun it). The stat and the one readdir stay synchronous; a single hanging read still blocks. A partial result is cached by folder mtime like a full one. Pinned by 3 tests in sdlc-skill-nudge.test.ts that fail on main.
