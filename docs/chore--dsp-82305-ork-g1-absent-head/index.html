The gate that rejected every PR older than itself

#4514 shipped the G1 advisory standards gate: pull_request_target checkouts of trusted code, a base floor, and the PR head as data. Its first real run, on #4513, exited rc=2. The head branch predated the gate, so head/configs/standards.json did not exist, and the driver passed the missing path straight to the reader.

1. Three trees, one judge

trusted/ base branch tip the gate code, the only tree anything runs from base/ PR base commit configs only: the floor a PR is judged by head/ PR head DATA ONLY: read as text, never executed

The floor already falls back: when the base lacks the configs, the trusted default-branch copy is the floor. The head side had no mirror. A head that predates the gate has neither config, so steps 2 and 4 fed the reader a path that was not there.

3. What the fix does

Each head-side step now checks [ -f head/<config> ] first. Absent file, skip with a notice: head predates the gate, nothing to widen (step 2, allowlist widening) and nothing to raise (step 4, baseline ratchet). Step 3 is untouched: it judges the head tree with floor allowlists and the floor baseline, so an absent head config can never hide a real violation.

4. Trust model, unchanged

runsonly trusted/base-branch code (check-frontmatter.py, this driver)
judged byfloor allowlists + floor baseline (base copy, else trusted copy)
read as datahead tree, head registry (step 2), head baseline (step 4)
skip whenthe head predates the gate: no registry to widen, no baseline to raise

The skip cannot launder debt: scenario C shows step 3 still reports NEW findings and the verdict stays red. A PR merges the gate forward only by carrying the configs itself; a head that has them is judged in full.
