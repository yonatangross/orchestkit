When Accept turns /ask into a stream

A client that gives Server-Sent Events a weight of zero is saying it cannot read them.

GET /ask?query=hooks&limit=1
Accept: application/json, text/event-stream;q=0

Before: production and local main

A case-sensitive substring match streams anyway, and misses a mixed-case opt-in.

SSE at q=0, JSON offered   SSE
Text/Event-Stream          JSON

After: local fix

Accept is read as media ranges: case-insensitive types and RFC 9110 weights.

SSE at q=0, JSON offered   JSON
Text/Event-Stream          SSE

Captured on 2026-11-24 against orchestkit.dev, a local next dev on main, and the same server with the fix. All responses were 200. SSE means text/event-stream; charset=utf-8. Every SSE and JSON body that kept its format had the same result checksum in all three runs. The explicit query, body and Prefer opt-ins still stream when Accept rejects SSE.
