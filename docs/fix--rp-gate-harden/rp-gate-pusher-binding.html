CI playground: fix/rp-gate-harden

Who actually produced this head? Binding the skip to the pusher.

This PR hardens the fail-closed gate from #5479 on two axes. First, the workflow sparse-checks out scripts/ci from pull_request.base.sha and runs that copy of the decision script and its allowlist, so a PR cannot weaken its own gate by editing either file. Second, a skip now needs one more fact: the triggering head sha must appear in the repository events feed as a PushEvent head on the release ref pushed by orchestkit-release-bot[bot]. Author and committer logins are only email attribution (forgeable by anyone who can push); the events feed records the real pusher. A human push carrying the head, a head not yet in the feed, and a feed that cannot be read all run every suite.

Event data

No effect: the gate runs the script checked out from the base sha. Editing scripts/ci/rp-diff-gate-decision.sh or the allowlist inside a PR can never weaken the gate that PR faces.

Why the events feed and not signatures

release-please commits with an app installation token and pushes over git, so its commits are unsigned and a GitHub App cannot hold a GPG key: commit.verification.verified can only ever mark commits made through the web API, which is not how the bot works. Requiring it would switch the skip off for every real release PR. The repository events feed instead records which actor pushed each head to each ref, so the check reads the repo events endpoint and requires the trigger sha to appear as a bot PushEvent head on refs/heads/release-please--*. If a non-bot PushEvent also carries that head the feed disagrees on who produced it, and conflicting evidence keeps the suites running. The feed keeps only recent events, so an old or not-yet-published head fails closed the same way.
