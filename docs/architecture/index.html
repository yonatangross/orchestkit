02How it works

  1. 1A tool call or session event fires; Claude Code runs node run-hook.mjs with the hook name and JSON on stdin.src/hooks/hooks.json:3-20
  2. 2The runner maps the hook name prefix to one split bundle and imports only that bundle.run-hook.mjs:77,405-412
  3. 3If a security hook's bundle is missing or broken, the runner blocks with exit 2 instead of failing open.run-hook.mjs:232,477,484-497
  4. 4The dispatcher runs its hooks; an opt-in session category cascade may call TypeSafe Jev.session-category-provider.ts:49,53
  5. 5Session hooks write the local SQLite registry: running, heartbeat, completed or crashed.session-registrar.ts:198,224; heartbeat.ts:47
  6. 6The runner sanitizes the result and prints JSON; an opt-in webhook can receive batched telemetry.run-hook.mjs:927; telemetry-sync.mjs:127-144
  1. 1A PR to main runs the build and 23 required checks, including plugin validation and secret scanning.gh api .../branches/main/protection
  2. 2On main, release-please keeps a release PR open; merging it cuts the vX.Y.Z tag.release-please.yml:27-37,77
  3. 3release.yml creates the GitHub release with build provenance and syncs plugins/ork to the dist repo.release.yml:31,152,293
  4. 4It opens the stable pin PR so the ork marketplace entry moves to the new tag, and pushes the docs MCP image.release.yml:158-161,176,437
  5. 5Users on the stable entry get the pinned tag; ork-alpha tracks main ahead of it..claude-plugin/marketplace.json:14-40
  6. 6Separately, Vercel deploys the docs site from main only.docs/site/vercel.json:3-7

Hover or click a step to light its path. Vendors are called by the hook runner or the docs site, never by each other. WAHA and Prodigi are not wired here and are not drawn.

03Layers, and why they are built this way

Plugin content

115 skills, 36 agents, 8 workflow scripts

Why Skills and agents are Markdown with frontmatter, so they ship as plain files and Claude Code loads them without a runtime.

One manifest lists what ships, and count tests fail a PR that drifts from it.

CLAUDE.md:27-28; manifests/ork.json:22-34

Hook runtime

163 hooks over 32 events, one Node runner, split bundles

Why Each event loads only its own bundle, which keeps cold start small on every tool call.

Security hooks fail closed: a missing bundle blocks rather than lets a call through.

run-hook.mjs:8,232,477

Local state

sessions.db on node:sqlite, per user

Why Built-in node:sqlite means no native addon to install or rebuild.

One file shared by all sessions on the machine lets hooks see siblings and mark crashed ones.

session-registry.ts:15-20,112

Docs site

Next.js 16 + Fumadocs on Vercel, /api/mcp, search

Why The MCP endpoint is stateless JSON-RPC over the same search the pages use, so agents and readers see one index.

A stdio image of the same server serves registries and offline clients.

docs/site/app/api/mcp/route.ts:8-13; Dockerfile:1-9

Release

release-please, tags, stable pin, dist repo, GHCR

Why Stable users install a pinned tag, so main can move without breaking them.

A slim dist repo carries only plugins/ork for directory size limits.

release.yml:156-161,277-280

03bDesign decisions

1Edit src/, ship generated plugins/

GainOne source of truth with a build that assembles real directories Claude Code can load.

CostGenerated files are committed and can drift; CI and count checks must guard them.

no ADR title matches

2One Node runner with per-event split bundles

GainSmall cold start on every hook call.

CostA broken bundle silences every hook in it until rebuilt.

no ADR title matches

3Security hooks fail closed

GainA bad install cannot quietly disable command and write guards.

CostA broken install blocks tool calls until the user rebuilds or reinstalls.

no ADR title matches

4Local SQLite registry on built-in node:sqlite

GainNo native dependency; sessions on one machine share state.

CostNeeds Node 22.5 or newer; unused tables had to be dropped later.

no ADR title matches

5Stable pin plus an alpha entry that tracks main

GainStable users get tagged releases; early users opt in to main.

CostTwo marketplace entries and a pin PR on every release.

no ADR title matches

6Public docs API with optional identity

GainAnonymous reads are the product; agents can still find auth metadata.

CostMore well-known endpoints to keep correct.

ADR: Optional agent identity

08Owners and risks

  • Owners in the repo: * @yonatangross, with .github/, src/hooks/, manifests/ and CLAUDE.md called out. VERIFIED .github/CODEOWNERS:5-11.
  • Owners outside the repo: the maintainer. CLAIMED.
  • Open risks:
  • CLAUDE.md says main and dev are protected (CLAUDE.md:62), but dev does not exist. gh api .../branches/dev/protection returns 404 "Branch not found" (VERIFIED 2026-11-06). Workflows still list dev in their branch filters (ci.yml:5,7, docs.yml:8,32). Contributors may target a branch that is not there.
  • Generated plugins/ is committed. A source edit without npm run build drifts from what users install; CI guards it (plugin-validation.yml, counts-validation), and hooks/dist/ is release-owned. VERIFIED CLAUDE.md:32,36.
  • A missing hook bundle blocks. Security hooks fail closed when their bundle cannot load (run-hook.mjs:232,477,484-497). Safe by design, but a broken install stops tool calls until rebuilt.
  • Counts are stamped in many places. manifests/ork.json:4 and marketplace.json say 36 agents and 163 hooks; marketplace.json description still says 43 commands. A count change needs bin/validate-counts.sh. VERIFIED CLAUDE.md:58, .claude-plugin/marketplace.json:5.
  • docs/coordination-architecture.md describes tables dropped in migration 005 (locks, settings_overrides, worktree_links; 4 matching lines). Read it as history for those tables.
  • WAHA (retired): leftover only as teaching content. 73 matching lines in 21 files, all in the api-design skill (source and its generated copies, for example src/skills/api-design/references/whatsapp-waha.md, src/skills/api-design/rules/messaging-integrations.md) and docs site generated data. Nothing wires it. VERIFIED git grep -n -i -I waha d21e50af2 | wc -l. Prodigi: 0 matches.
