The model reads each skill's one-line description to decide whether a plain request is a job for that skill. These three lines did not carry the words people type for those jobs, and ork:auto had no route for opening a PR. The texts below are the ones in this branch and on main.

2 / Routes in ork:auto

RouteChange
open-prNew row routing to create-pr. Called open-pr, not promote, so it stays apart from the holdout-promotion gate and from promoting a branch to production.
diagnoseSignals add triage, root cause and culprit commit.
reviewSignals add the word diff. A PR to read is review, a PR to open is open-pr.

The routing rules also say what each skill cannot take: fix-issue resolves its target from an issue number or URL, review-pr takes a PR, a branch or a base...head range (not pasted diff text), and create-pr opens the PR with gh and has no text-only mode.

3 / The offline fire cases

Nine natural prompts, none naming a skill. For each, the test checks without a model call that the expected skill is the best lexical match in the listing and leads the runner-up by at least 1.0 point, and that the ork:auto table has a row for the intent that points at it. A pasted diff is dropped before scoring, because its code identifiers are not the request (an expect(...) line once scored as the name of another skill). The minimum is enforced in the test, with planted controls that fail on a tie, on a thin win and on the wrong skill first. Two cases are recorded as gaps the skills do not cover, and they print SKIP, never pass.

What this does not show
