Glyph card as an MCP App, no SDK

Verdict: one MCP tool returns both an interactive UI (a ui:// resource) and a text card as a fallback. A host that supports MCP Apps draws the card; every other host shows the text.

PR 4663, branch feat/genui-mcp-spike. One file: src/skills/mcp-visual-output/scripts/glyph-card-server.mjs, with tests in tests/unit/test-mcp-glyph-card.mjs.

02 / What the PR adds

  
    
    
  • The tool declares _meta.ui.resourceUri, the older ui/resourceUri key, and the ChatGPT alias openai/outputTemplate.
    • 
    
  • The resource is served as text/html;profile=mcp-app and draws with textContent only, so a hostile label never becomes HTML.
    • 
    
  • HTTP mode rejects a non-local Host or Origin with 403, unless one name is allowed with --allow-host.
    • 
    
  • Unit tests: 10 pass, 0 fail, per the PR body.
    • 
  


  
03 / Not proven yet

  
    
    
  • No real host (ChatGPT, claude.ai) has drawn the card yet. That needs a public HTTPS URL and an operator step.
    • 
    
  • In Claude Code the model receives the structuredContent JSON when it is present, not the text card.
    • 
    
  • No authentication. This is a proof of concept, not a library.
