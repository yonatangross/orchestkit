review-pr: a proven-by-a-run tier for critical and high findings

Until now a critical or high finding stood whenever no refuter killed it. The fanout now also says which of them carry a run. A finding is proven only with the command it ran, the output it printed and the output the intent requires.

Try a finding

The rule

LabelWhen
provencritical or high after refutation, three parts hold real text, and the output differs from the required output.
only-unrefutedcritical or high after refutation, but no run behind it. It stands because no refuter killed it.
ground-trutha failing check restated; it is a run already and is never refuted.
not-requiredmedium, low, or downgraded below high.
in neither listkilled by the refuters.

What did not change

The verdict, the refuter votes, the quorum and the spawn ceiling are untouched, and the refuter prompt never carries the run text. The script reads the three parts as text and does not re-run the command, so re-run it before quoting the output as seen.

Runs are opt-in. The new allowRuns argument is off by default because PR code is untrusted input. Off, reviewers are told not to execute anything from the diff and critical or high findings come back only unrefuted. Pass it only for a same-repository PR from a trusted author in an isolated checkout.

The rule that a finding counts as proven only when a run shows it is adapted from the interrogate skill of pstack by Lauren Tan (MIT License, github.com/cursor/plugins).
