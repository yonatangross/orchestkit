Keep the tool.call context, and stop glob-only matches

Three faults in the lesson-cards mod, each pinned by a test written first.

1. A hook adds to the context, it never replaces it

With memory-lens and lesson-cards both on, lesson-cards returned its own context list and dropped the entry memory-lens had attached. Claude Code then printed "returned the wrong shape" and skipped the hook.

Context from the hook belowContext lesson-cards returns
["memory note"]["memory note", "[lesson:...]"]
["ok", "", 42]["ok", "[lesson:...]"] (empty and non-string entries dropped)

2. A file entry needs its content regex, and exclude paths are substrings

In the live corpus, 18 of 31 entries carry a file glob and a content regex in pattern or trigger_pattern, with no check_patterns. The matcher ignored the regex, so the block entry langfuse-v4-client (**/*.py) asked "Proceed anyway?" on every Python write. Its exclude_paths (/tests/, .md) are plain substrings that were read as full-path globs and never matched.
