Seventeen Paths, One Regex

The release-please build step refuses to execute a release branch whose diff from main touches any path outside the ALLOWED regex in .github/workflows/release-please.yml. The extra-files list in .release-please-config.json is what puts version-stamped files on that branch. One entry ALLOWED does not cover, and every release is blocked (#4173). Nothing checked the two files against each other.

The measurement

Measured on main before this change: 19 extra-file entries parse to 17 unique paths, and all 17 match ALLOWED today. So the new test passes on main, and the mutation proofs exist to show it is able to fail:

M-a: drop the .devin-plugin alternative from ALLOWED → 19 passed, 1 failed, naming .devin-plugin/plugin.json
M-b: add a fake extra-files path docs/fake-mutation-path.md → 20 passed, 1 failed, naming it
M-c: rename ALLOWED= to ALLOWED2= → 1 passed, 2 failed on the exactly-one assertion
The check, live in your browser

The test parses the unique paths, finds the ALLOWED='...' assignment by its text, compiles it with grep -E (the same engine the workflow step uses), and asserts every path matches. Same idea here, against a paste of today's ALLOWED and the 17 paths:

17 unique extra-files paths parsed → press the button to check them

The fix is one test, tests/ci/test-release-extra-files-allowed.sh, in the suite ci.yml already runs on every PR. No workflow or config file changes.
