OrchestKit · skills/quickviz

The skill pointed at a file that does not ship with it.

quickviz told the model to use the glyph vocabulary "defined in src/rules/visual-style.md". That path exists in the repo and nowhere in the installed plugin, so at runtime the reference resolved to nothing and the vocabulary the rule depends on was never loaded.

Resolving the rule at runtime


    

  


  

    
What ships in the bundle

    

      A skill can only reference files packaged under its own directory. Anything addressed as
      src/... is a repo path and is absent from the installed plugin.

Why it mattered

    

      The twelve-glyph vocabulary is what makes quickviz output consistent, and it
      is enforced by validate-visual-style.py on PR titles and bodies. A rule that
      cannot load is a rule that silently is not applied, while the validator downstream still holds output
      to it. That gap is the whole defect: the standard was enforced but never delivered.
    

  


  

    Ship the visual-style rules file inside the quickviz skill bundle and reference it by its bundle-relative path, so the glyph vocabulary actually resolves when the plugin is installed.
