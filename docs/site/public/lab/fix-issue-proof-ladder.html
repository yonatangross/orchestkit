fix-issue: prove the safety fact before a fix ships

A blast-radius write-up that sounds right is worthless: it reads as convincing whether or not it is true. So fix-issue now finds the one fact a fix is safe because of and proves it by running real code. The four user questions are gone.

Example fix: a cache cleanup call. The fact it is safe because of: this call only drops entries that are already dead and does nothing else.

What changed

fix-issue reference. fix-blast-radius.md no longer asks the user. It names the one safety fact, pushes it down the ladder, and writes the fact, its step and the risks into the PR body. A fact below step 4 is written down as unproven.

review-pr rubric. One new criterion, safety_proof, with weight 0 so the other weights and the verdict maths do not move. A change states its safety fact at step 4, or the reviewer marks it unproven. It is a mark, not a blocker.

The method is adapted from the blast-radius skill of pstack by Lauren Tan (MIT License, github.com/cursor/plugins). The notice is kept in the reference.
