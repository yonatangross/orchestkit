When search gets an extra prefix

OpenAPI clients append the operation path /api/search to the selected server URL. Compare the URLs and HTTP responses from both versions of the spec.

Two servers were advertised. The second generates a search URL that does not exist.

Requests from the advertised servers

  • /api/search?query=hooks200 OK
  • /api/v1/api/search?query=hooks404 Not Found

Direct request to the versioned alias

  • /api/v1/search?query=hooks200 OK

The alias is documented and still works. It is not a server base URL for this spec.

Recorded HTTP probes against the local Next.js server, not live requests from this page. Production reproduced the same before results.
