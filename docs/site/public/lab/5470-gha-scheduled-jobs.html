CI playground: fix/gha-scheduled-jobs

Which PRs skip the heavy suites?

This PR adds a reusable gate (rp-diff-gate.yml) that lets the expensive CI jobs skip themselves on release-please PRs: those diffs touch only release-owned outputs, so 61 checks fired on #5463 for a version/changelog-only change. Fill in the event data below and see the gate's verdict. The file allowlist is the same list the shipped script uses (scripts/ci/rp-diff-gate-allowlist.txt).

Why this gate exists

A release-please PR bumps versions and regenerates changelogs and dist bundles. Nothing in it can break a hook test or an eval, yet the full suite ran anyway. The gate classifies every changed path against release-owned shapes only: manifest and plugin.json files, hook dist/ bundles, generated docs data, changelogs and version pins. One ordinary source file, the wrong bot login or a non-release branch turns the skip off. A first review found the gate had to know the repository's own release bot (orchestkit-release-bot[bot], not release-please[bot]) and that a bare plugins/* glob would have counted real plugin source as release output; both are fixed and covered by tests/ci/test-rp-diff-gate.sh.

Source of truth for the demo: scripts/ci/rp-diff-gate-allowlist.txt and scripts/ci/rp-diff-gate-decision.sh on this branch.
