ORCHESTKIT LAB · PR-4188

Lab Data, Generated at Build

The Lab aggregate used to be one committed file that every playground PR had to edit, so any two PRs in flight collided. Now each Lab entry is its own fragment and the aggregate is generated, so there is nothing left to collide on.

The flow

One fragment per entry

Source of truth: docs/site/lab-manifest/<slug>.json, exactly one entry per file, owned by exactly one PR.

fragment JSON committed → lab-manifest.mjs prebuild · predev · pretest → lab-data.ts generated, untracked

The generator also refreshes the docs/site/public/lab/ copies, which stay committed. The aggregate docs/site/lib/generated/lab-data.ts is gitignored: a file that is not in the index cannot conflict. That ends the issue 4181 conflict class and replaces the union merge driver added for issue 4184, which is removed together with its only rule in .gitattributes.
