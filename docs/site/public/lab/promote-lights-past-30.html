promote-lights finds the promote PR past 30

Session start listed open promote PRs with one unfiltered gh pr list page, which holds at most 30 entries. A promote PR past position 30 was silently missed. Now two server side filtered queries run instead.

Before

One call: gh pr list --base main --state open returns entries 1 to 30. The promote PR at position 35 never arrives, so no lights are tracked.

After

Two calls, each filtered server side with an explicit limit, merged and deduped by PR number:

gh pr list --base main --head dev --state open --limit 100 gh pr list --base main --label promote --state open --limit 100
