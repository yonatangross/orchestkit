The Release Rebuild Stops Running the Whole Suite

The step that rebuilds hook bundles on the release branch is the one place stale bundles get fixed before a release ships. Measured over the 46 Release runs since 2026-09-15 (issue #4183), its rebuild cost 219-272s per run and its push once lost an 84s race. The window is what the bot's own push runs, not what the bundles need.

Where the 272s went

Run 35070229993, step log timestamps, 2026-09-16:

npm ci (root + hooks): ~2s: the root package.json has zero dependencies
full plugin build: ~65s: assembles every plugin; the step only commits two dist dirs
pre-push suite in the bot's push: ~204s: typecheck, build verify, 71 unit tests, security, hook vitest

Phase 1 proved byte-identical: building only src/hooks (esbuild, 169ms of it) plus the dist rsync reproduces src/hooks/dist and plugins/ork/hooks/dist exactly, with a real source mutation in both clones (diff -r rc=0).

Before and after, same step name
before: npm ci (root) + npm ci (hooks) + npm run build (root) + push that runs the pre-push suite
after: npm ci + esbuild in src/hooks + dist rsync + push --no-verify; the release PR's own CI runs the full suite
run 35070229993: 272s total = 2s installs + 65s full build + 24s pre-commit + 204s pre-push suite in the bot's push

No new trigger, job or concurrency group: the one measured race loss self-healed on the next run, so the fix only shrinks the window the step itself opens. Fail-closed arms unchanged.
