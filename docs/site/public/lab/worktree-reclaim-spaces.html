OrchestKit / safety regression

Spaces are part of the path.

Reclaiming my wt/node_modules must never remove my/node_modules. The old parser split the worktree path at its first space, then passed the wrong destination to a correctly quoted removal command.

Real fixture, not a simulated deletion

A throwaway Git repository has a linked worktree named my wt, stale dependency directories, and an unrelated sibling my/node_modules/decoy. These excerpts came from running the script itself in dry-run and apply modes. Temporary root prefixes and aligned columns are omitted for readability.

Before: wrong directory

DRY RUN
my  LINK  node_modules  reclaims 0 MB

APPLY
my  LINK  node_modules  reclaims 0 MB

FAIL decoy deleted
FAIL real worktree not reclaimed

After: exact worktree path

DRY RUN
my wt  LINK  node_modules  reclaims 0 MB

APPLY
my wt  LINK  node_modules  reclaims 0 MB

PASS decoy preserved
PASS real worktree reclaimed

The fix and its proof

Keep everything after the porcelain worktree prefix. Read paths without trimming whitespace. Replace mapfile with a Bash 3.2-compatible array loop.

PASS dry-run reports the real main and worktree paths
PASS dry-run leaves directories unchanged
PASS apply preserves the unrelated decoy
PASS apply reclaims the real worktree directory

The existing worktree shell suite now exercises a space in both the main repository and linked worktree paths. The suite also passed in Docker with GNU Bash 3.2.57.
