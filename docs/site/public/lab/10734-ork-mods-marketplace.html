The mods were never inside the plugin

PR #4587 registers memory-lens in the marketplace and turns the missing-entry warning into an error.

[0] The packaging model

A mod is its own plugin. Each one ships as a separate marketplace entry pointing at mods/<name>, installed with claude plugin install <name>@orchestkit. Nothing about plugins/ork was supposed to contain them. Pick a mod to see its entry status before and after this PR, its registered events, and the install command.





[1] What was broken
memory-lens landed in #4530 with no marketplace entry, so claude plugin install memory-lens@orchestkit had nothing to resolve. The structure gate compared 3 entries to 4 directories and only warned, so CI stayed green. Three descriptions still asked for CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1, a variable Claude Code 2.1.287 and later ignore.


[2] Bug check on Claude Code 2.1.288
Each mod loaded with claude -p --plugin-dir mods/<name>. All four were admitted by the built-in sec-default guard and registered their declared events.

[4] Decisions
The fix lands on the packaging surface that exists, not on a new build step that would copy mods into a tree Claude Code never reads. The PR stays in draft; the conductor controls ready status and merge.


[5] Impact
After merge, claude plugin install memory-lens@orchestkit resolves. The next mod added without an entry fails CI instead of warning. Mods stay opt-in: installing ork still installs no mod by itself.
