hooks / npm-ci symlink guard

The guard stops guessing what bash will do.

Seventeen Vercel Security Review findings said the same thing in seventeen shapes: the guard's hand-rolled shell parser read a different command than bash ran, so a npm ci could empty a symlinked node_modules the probe never visited. Reproduced against the live guard, twelve were real. Every one is now closed at the mechanism: the parser fails closed on what it cannot model instead of confidently parsing it wrong.

Pick an attack shape

Each shape below bypassed the old guard: bash lands the install inside the linked directory while the guard probes a decoy. The linked dir here is always /lw/node_modules (or the one named in the note).
