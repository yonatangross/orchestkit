The capture
that never ran.

Seven places in the page-serve scripts read out="$(cmd)"; rc=$?. Under set -e the assignment itself is the failing command: the script exits on it, so rc=$? never runs, the error branch is dead code, and whatever cleanup sat behind it never fires. status.sh exited 7 on a dead pid despite documenting "exit 0 always"; serve.sh leaked its python http.server when portless alias failed.

The other two findings

-  if ! git diff --quiet || ! git diff --cached --quiet; then  # blind to untracked
-  git worktree remove "$worktree_path" --force                 # no prompt, files gone
+  if [ -n "$(git -C "$worktree_path" status --porcelain)" ]; then
+  [[ "$confirmed" == "1" ]] && git worktree remove "$p" --force || git worktree remove "$p"

worktree-setup.sh cleanup asked git diff whether the tree was dirty. Untracked files are invisible to it, so a worktree holding only new files was force-removed with no prompt. The guard now reads status --porcelain and the worktree match is an exact porcelain line, not a substring that could hit a sibling.

-  --live) share_mode="funnel"; live_duration_hours="${2:-4}"; shift 2 ;;
+  --live) share_mode="funnel"; live_duration_hours="4"
+          if [[ "${2:-}" =~ ^[0-9]+$ ]]; then live_duration_hours="$2"; shift; fi
+          shift ;;

boot.sh --live as the last argument ran shift 2 with one argument left, which exits 1 under errexit before the documented 4h default ever applied. A failing tailscale status (and the monorepo portless list) aborted after the dev server started and before dev-stack.json was written, orphaning the wrapper; both captures are now wrapped in { ...; } || true.
