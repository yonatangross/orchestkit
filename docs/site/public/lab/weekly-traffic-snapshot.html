The week that outlives the 14-day window

GitHub exposes repository traffic (views, clones, popular paths, referrers) through a rolling 14-day window, then the numbers are gone. OrchestKit #4071 adds a Monday 06:00 UTC workflow that reads the four endpoints, folds the PREVIOUS full week into ONE JSONL row, and opens a PR carrying the row to docs/traffic/snapshots.jsonl. The ledger is committed, so history outlives the window and every week is reviewable. This page shows the row shape, the fail-closed rules, and the two growth-docs deliverables that ship with it.

One row per previous full week

The run measures [previous Monday 00:00 UTC, current Monday 00:00 UTC). The row carries daily buckets for that window and labels the two 14-day lists as what they are. This is a sample row, the same shape the test fixtures pin:

Window sums are computed from the buckets inside the week, which is why they can differ from GitHub's own 14-day top-level count. Popular paths and referrers come from the API with a fixed trailing 14-day window (no weekly variant exists), so the row says window_days: 14 instead of pretending they are weekly.

Fail-closed: no row on a failed read

A zero row written during an API outage would read as a traffic collapse that never happened. The script validates every read and refuses to write unless ALL four endpoints answer cleanly. Flip a failure on and watch the run refuse:

row written

All four reads succeeded and validated; 7 daily buckets inside the measured week. Exactly one row appended for week 2026-09-07.

The row is written only after every read succeeded AND validated: non-200, unparseable body, a non-integer or negative field, or zero buckets inside the measured week each abort with nothing written. Idempotency is on top of that: a week already in the ledger makes the run exit 0 with no API calls at all, so re-dispatching cannot duplicate a row or a PR.

The credit line policy

External mentions carry one exact line, word for word, every time, so attribution stays clean in referrer data. The kit line:

OrchestKit is a Claude Code plugin: reusable skills, specialist agents, and lifecycle hooks, packaged as one installable plugin. https://github.com/yonatangross/orchestkit

The per-skill table has exactly one line for each of the 36 user-invocable public skills. Pick one:


    Skills not in the table are internal-only: drafts name them never and use the kit line instead. Credit lines never carry numbers; numbers age and drafts must not claim unverified figures.

How the week lands

  

    

      
stepwhat it does

      
        
cron 0 6 * * 1 + workflow_dispatch Mondays 06:00 UTC, manual re-dispatch allowed, idempotent per week

        
read four endpointsgh api traffic/views, traffic/clones, traffic/popular/paths, traffic/popular/referrers

        
validate + aggregateprevious full week only; sums from in-window buckets; refuse empty weeks

        
append one rowdocs/traffic/snapshots.jsonl, one JSONL line, seeded empty

        
open a PRbranch traffic/snapshot-<week>, never a direct push to main; the row is the PR body
