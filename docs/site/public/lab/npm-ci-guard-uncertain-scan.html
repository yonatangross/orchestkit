npm ci guard: comments and sh -c scripts

Running npm ci where node_modules is a symlink empties the tree the link points at. The guard stops that. It now reads two more shapes: a command with a comment that holds a lone backtick or quote, and a script passed to sh -c in single quotes.

What changed

The guard reads a command several ways: with substitutions blanked out, as raw text, and each $(...) or backtick body on its own. Two gaps are closed:

Comments and unclosed openers. The reader used to stop at the first quote, $( or backtick that never closed, so everything after it went unread. It now skips a comment to the end of its line, as the shell does, and steps over an unclosed opener instead of stopping.

Scripts in single quotes. To the outer shell, sh -c '...' is inert text. The script still runs, so the guard now reads it with the same readings as the outer command, three levels deep.
