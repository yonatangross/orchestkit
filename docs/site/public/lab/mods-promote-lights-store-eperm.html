promote-lights: a store it cannot write no longer kills the band

promote-lights 0.0.14. In a sandboxed Claude Code session the mod store under ~/.claude is not writable, so session.start threw on its first $.store.delete and no band ever drew. Now every store call goes through one wrapper: on the first failure the lights live in memory for that process, and the status line says lights: store unavailable once.

Measured 2026-10-20 (mods dogfood): [ERROR] promote-lights: session.start hook skipped: threw promote-lights@orchestkit: $.store.delete failed: EPERM: operation not permitted, mkdir '/Users/.../.claude/...'. Tests: 3 new, red before the fix, 126 passed after.

Try it

What stays the same

Per-session keys, the /clear token rotation, and "only this session's lights" are unchanged: the memory copy is per process, so another session never reads it. A writable store behaves exactly as before; the wrapper only changes the failure path.
