Stop the stable pin from cutting a release

Verdict: one entry added to exclude-paths in .release-please-config.json: .claude-plugin. The stable-channel pin commit (#4867) touches only .claude-plugin/marketplace.json; today it counts as a chore in a visible changelog section, so every pin opens a release PR (#4868, 10.0.2, with nothing in it but the pin).

Branch fix/release-please-exclude-marketplace, from main at afca76a9.

Why the directory and not the file

release-please matches an exclude-paths entry as a directory prefix only: file.indexOf(`${path}/`) === 0 in CommitExclude.isRelevant. A file entry such as .claude-plugin/marketplace.json would need the path .claude-plugin/marketplace.json/ to match, so it never excludes anything. The same code is in release-please 17.11.2 and in the bundle of the pinned action (release-please-action v5.0.0, sha 45996ed1). .claude-plugin/ holds one file today, marketplace.json.

Counted means the commit reaches the release PR. A release PR opens only when at least one commit is counted.

Side effects

  • A hand commit that touches only .claude-plugin/ (today: only marketplace.json) cuts no release and does not appear in the changelog.
  • A commit that touches marketplace.json and anything outside .claude-plugin/ still counts, as before.
  • Release-please still bumps $.version in marketplace.json through extra-files; exclude-paths filters commits, not the files a release writes.
  • Any file added to .claude-plugin/ later is excluded the same way.
