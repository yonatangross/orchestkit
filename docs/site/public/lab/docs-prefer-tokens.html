When Prefer changes the response

Only a top-level preference name should start an async job or switch JSON to an event stream.

Prefer: return=representation; note="respond-async"

Before: production and local main

The APIs mistake the quoted parameter for a request to change formats.

/api/md/batch   202 application/json
Preference-Applied: respond-async
/ask            200 text/event-stream

After: local fix

Both APIs return JSON normally. No async preference is applied.

/api/md/batch   200 application/json
No Preference-Applied header
/ask            200 application/json

Controls: identical in all three runs
