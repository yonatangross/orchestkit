A Jev shadow over every expect step

The expect agent already picks a browser action per step from the accessibility tree. This adds a second, typed opinion: one Jev request judges the same step, and the report logs whether the two picks agree. Shadow only, off by default, and the shadow pick never drives the browser.

1request per enabled step
4questions: 1 Choice + 3 Nouls
60element cap, from config
0shadow picks executed

Try it: the flag is the whole story

Flip ORK_EXPECT_JEV_SHADOW and watch the step. Off is a true no-op: the step runs exactly as before, zero requests leave, zero report lines appear. On adds one bounded judgment beside the model pick.

ORK_EXPECT_JEV_SHADOW
flag off -> jev-shadow.sh exits before python or the network. no request, no JEV_SHADOW line, the model action is the only action.

What leaves while the flag is on

    
One HTTPS POST per step to the configured endpoint, carrying only the fields the four questions need:

    
    
      
  • the step goal and the last verify result, each redacted and truncated;
    • 
      
  • up to 60 interactive elements as ref / role / accessible-name triples.
    • 
    

    
Never sent: page text beyond accessible names, cookies, tokens, URLs, the model pick string, any full message body or command line. Outbound strings are JSON-escape-decoded before the secret patterns run, so a planted token is caught in raw and escaped encodings alike.

  


  

    
Shadow means shadow

    
The model action remains the action the agent executes. The Jev pick lands in the report beside it with the full probability distribution, the three noul flags, per-step agreement, and latency against the 400 ms budget. It is a measurement, not a driver.
