review-pr posts only when you type --post

orchestkit #4675, PR #4678. A review run posted a review nobody asked for; posting is now opt-in in code.

Verdict

No post without your word. /ork:review-pr 4668 prints the review and stops. /ork:review-pr 4668 --post may post a comment or a request-changes review to PR 4668 only. An approve, or a first line that reads LAND, HOLD or XREVIEW, also needs --post-verdict.

How a post is decided

you type  /ork:review-pr 4668 --post
   │
   ▼  (CC writes that turn to the transcript; every later entry links to it by parentUuid)
model calls  node post-review.mjs --pr 4668 --event comment --body-file /tmp/r.md --post
   │
   ▼  skill/review-post-gate (PreToolUse)
   ├─ the nearest human turn on THIS call's chain is your /ork:review-pr line?   no → deny
   ├─ you typed --post?                                                           no → deny
   ├─ --pr is exactly the PR you typed after the command, once?                  no → deny
   ├─ a bare number, and the shell is at the session project root?               no → deny
   ├─ approve or post-verdict in the call, and you typed --post-verdict?          no → deny
   └─ one plain command (letters, digits, - _ . / : space), no --repo?           no → deny
   │
   ▼  post-review.mjs
   ├─ body file: one regular file under /tmp, no second hard link, same inode as checked, <= 64 KB, no key shapes
   └─ gh gets the checked bytes on stdin (--body-file -)

Limit

The gate reads command text while the model holds a full gh login. A renamed copy of post-review.mjs, a script file written first, or an in-place edit of the real transcript entry through a path built at run time is not seen. It stops an over-eager post, not a model set on getting around it. The fail-closed layer is no gh write credentials in the run: #4677.
