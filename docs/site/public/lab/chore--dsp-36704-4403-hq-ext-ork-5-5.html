The header nobody asked for

PR playground for #4403: a PreToolUse hook rewrote files in consumer repos, and nobody saw it until review.

src/pretool/input-mod/write-headers.ts ran on every Write. When the target file did not exist yet, it returned an updatedInput that prepended a banner, # Generated by OrchestKit Claude Plugin plus a # Created: date, in the comment syntax of the file type. The change was invisible in the tool call the author approved.

In a consumer repo six committed files carried it, all under .github/: three workflows, one issue template, two scripts. A reviewer called it plugin junk on a release PR and it was removed by hand. For shell scripts it could also invent a #!/bin/bash shebang the author never wrote.

FileChange

      
        
src/hooks/src/pretool/input-mod/write-headers.ts
            The header builder, the existsSync probe and the updatedInput path are gone. The hook stays registered as a compatibility no-op and returns silent success.

        
src/hooks/src/pretool/write-edit/sync-write-edit-dispatcher.ts
            Comments only: write-headers is documented as a no-op in the dispatcher order.

        
src/hooks/src/__tests__/pretool/write-headers.test.ts
            Regression test: the hook never returns an updated input, for every file type the old code touched.

        
src/hooks/scripts/fh-ready-baseline.json (and the plugins/ork copy)
            write-headers no longer imports node:fs, so it leaves the FH-ready ratchet baseline. fh-ready-check reports 110 grandfathered, 0 new.
