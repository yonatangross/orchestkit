Two-pass review: the standards pass

The builder makes it work. A separate pass checks the repo's standards. Card pocock-two-pass, after Matt Pocock, "Fixing the PR Bottleneck".

Verdict

One agent per PR, with every standard and a self-refute step, found the same finding as the 11-agent fan-out for about a tenth of the tokens. That is now the default. --rules stays opt-in.

Flow

builder ──▶ head ──▶ STANDARDS PASS (read-only) ──▶ findings
                                                      │
FIX LANE (new session, red test first, commits) ◀─────┘
   │
   ▼
LAND reviewer (cross-provider) reviews the final head

The pass never commits and never gives LAND or HOLD. FINDINGS=0 skips the fix lane. One fix round, no loop.

The standards file

.github/review-standards.md, owned by the repo. Claude Code loads CLAUDE.md and .claude/rules/** into every session, so those reach the builder. It does not load .github/*.md. At most 20 rules and 3 KB. A leading [glob] limits a rule to matching paths. The pass reads it from the PR's base branch, so a PR cannot rewrite the rules it is checked against. A repo without the file skips the pass and logs one line.
