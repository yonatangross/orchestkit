Signed skill-autoheal commits

Skill Build Autoheal regenerates committed build output on a PR that only edited src/. It used to build the commit on the runner and push it, which left an unsigned commit on the PR branch (#5012). It now creates the commit through the GitHub API, which GitHub signs.

Before

  • Runner runs git commit as github-actions[bot]
  • Pushes it with the App token
  • Commit signature: none (unverified)
  • Security review legs flag it; removing it needs a force-push

After

  • Runner stages the gated paths and reads the staged diff
  • scripts/ci/api-commit.mjs uploads blobs, builds the tree, creates the commit with no author set
  • GitHub signs it: verification.verified = true
  • Branch moves fast-forward only, and only if the commit came back verified

Guards in the new path

CheckIf it fails
Each blob id GitHub returns equals the local git blob idStop, nothing committed
Tree id GitHub returns equals local git write-treeStop before creating the commit
New commit reports verification.verified trueBranch left untouched, check fails with the regenerate command
Ref update uses force: falseA branch that moved meanwhile is a 422, never an overwrite

Narrower credentials

  • The App token is minted after npm ci and the build, so the PR code those steps run never sees it.
  • Checkout uses persist-credentials: false; no token is left in .git/config.
  • GITHUB_TOKEN stays contents: read; the App token keeps contents: write only, as before.

Tests

tests/ci/test-skill-autobuild-api-commit.mjs runs the script against a fake GitHub API: drift with an edit, a new file, a deletion and an exec-bit change; an unverified commit; a tree mismatch; and no drift. It also fails if the workflow runs a push or commit on the runner again.
