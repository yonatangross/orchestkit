Workflow PRs open unarmed

Two workflows armed auto-merge on the PR they had just opened. The required checks are CI only, so the v10.2.0 stable pin (#4913) merged before anyone reviewed it. Now workflows only open PRs, and a lint fails if a merge or arm comes back.

How the lint reads a workflow

  • Parses the YAML, so folded and literal run: values are judged after folding. A file it cannot parse is a finding.
  • Joins backslash-newlines the way the shell does (nothing in their place), then splits each run: value with shell quoting rules and also scans it with quotes removed. A hit from either counts.
  • Flags any gh pr merge (global flags before pr included), a variable gh pr subcommand, the REST pulls/<n>/merge endpoint, the GraphQL merge, auto-merge and enqueue mutations, pulls.merge or pulls["merge"] in github-script, and automerge actions.

Caveats

  • A GET of pulls/<n>/merge (is it merged?) is flagged too, on purpose. Read pulls/<n> and its merged field instead.
  • The skill docs that teach gh pr merge --auto are guidance for a user's own repo and are not scanned.
  • A spelling found later that this misses goes to a follow-up issue, not a bigger rule in this PR.
