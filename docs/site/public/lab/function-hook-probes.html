chore/function-hook-probes · playground · 2026-09-19

R1 and R3, settled by the engine's own debug log.

The 2026-09-18 cc-mods adoption brief left two function-hook questions open: does a user-tier hooks module load with CLAUDE_CODE_ENABLE_FUNCTION_HOOKS unset (R1), and does a tool.list answer change what a subagent is offered (R3). tests/probes/function-hooks-probe.sh turns both into a repeatable probe: four claude -p calls on --model haiku --no-session-persistence, verdicts grepped out of each run's --debug-file. Measured below on claude --version = 2.1.277.

The four lines the script printed

REFUTED
R1-unset
user-tier hooks modules not loaded; rollout flag off from the default (a cold GrowthBook cache, no payload yet)
VERIFIED
R1-set
lesson-cards loaded (tier user); 2 settle lines logged
REFUTED
R3-main
tool.list hook loaded tier user but never dispatched; Read still offered (model YES)
REFUTED
R3-subagent
subagent still offered Read and tool.list never dispatched; SUBAGENT:YES

What the engine actually did

R1: the gate is per account and per cache state, not per binary

The flag check is env ?? GrowthBook ?? false. With the variable truly unset (env -u; an empty assignment is itself an override), this account's debug log reads installed plugins' hooks modules not loaded: rollout flag (tengu_plugin_hooks_modules) is off, from the default (a cold GrowthBook cache, no payload yet). The same run with the variable set to 1 loads lesson-cards@inline at tier user and logs session.start and tool.call settles. Built-in plugins load regardless either way.

R3: tool.list is not in the offered-set path at all

A one-file probe mod (tests/probes/tool-list-mod) answers tool.list with Read filtered out and writes one marker file per dispatch. Across both runs the debug log shows zero tool.list settles and zero markers: the main loop's offered tools and the Explore subagent's are built without consulting it. What did run for tool offering: tool.describe (245 settles), command.describe (600), agent.offer, and one agent.spawn when the subagent launched. So on this build a tool.list answer changes neither list; the brief's subtractive-scoping row needs a different event.

The commands

# R1, flag truly unset (an empty assignment is itself an override)
env -u CLAUDE_CODE_ENABLE_FUNCTION_HOOKS claude --plugin-dir mods/lesson-cards \
  -p "run: echo hi" --model haiku --no-session-persistence --debug-file dbg.log

# R1, flag forced on
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --plugin-dir mods/lesson-cards \
  -p "run: echo hi" --model haiku --no-session-persistence --debug-file dbg.log

# R3, probe mod loaded; main loop, then a run that spawns Explore
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --plugin-dir tests/probes/tool-list-mod \
  -p "<ask: is a tool named Read in your list?>" --model haiku \
  --no-session-persistence --debug-file dbg.log

Reproduce

./tests/probes/function-hooks-probe.sh   # prints the four lines, cleans its temp dir, exits 0

Evidence lives in each run's --debug-file: hooks module <name> loaded (..., tier user); events: ... for loads, hooks module <name> <event> settled in <ms> per dispatch, and the rollout-flag line naming the deciding source when the gate is off. INCONCLUSIVE is reserved for an empty or errored call.
