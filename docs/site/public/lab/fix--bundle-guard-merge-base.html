The frozen base.sha that taxed every open PR

The hook-bundle guard diffed github.event.pull_request.base.sha (frozen when the PR opened) against the merge ref. When release-please's bundle rebuild landed on main afterwards, that diff showed main's newer bundles as if the PR had authored them: every open PR red, and the printed remedy (git checkout BASE_SHA -- dist/) would have reverted the newer bundles. The fix diffs merge-base(origin/base, HEAD), which on the merge ref is the current base tip, and skips dist paths whose content is identical to that tip (inherited, not authored, the #4277 pre-commit exception).

Replay a scenario

guarddiff rangedist changed?verdict
before: frozen base.sha
after: merge-base(current tip)

Mirror of the lifted step in tests/ci/test-hook-bundle-guard.sh: arms A/C are green under the new guard (both were red under the old one); arms B/D stay red because the dist edit is genuinely authored.
