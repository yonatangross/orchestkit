CI batch: three gates that measured less than they said

Branch fix/batch-ork-ci-4528-4752-4697. One commit per issue: #4528, #4752, #4697.

Verdict. The weekly traffic ledger no longer loses about 4 days a week, a rebuilt traffic PR shows the numbers its data file holds, and the skill activation gate no longer passes a skill whose only "trigger" is the line background: false. Three skills that passed that way are now wired or explicitly allowlisted.

1. #4528: a short week is refreshed, not skipped forever

The GitHub traffic API lags about 5 days, so the Monday run sees roughly 3 of the previous week's 7 days. The script skipped any week that already had a row, so the other 4 days were never read, and they leave the API's 14-day span a week later.

Before: skip a recorded week

After: refresh a short week while the API holds it

A row is replaced in place only when the new read has more days; other lines stay byte-identical; a complete ledger still makes no API call; a short week already outside the 14-day span stays as recorded.

2. #4752: a rebuild refreshes the open PR's body

Before

gh pr create ... || echo "::warning::gh pr create failed"
# PR #4717 kept the first build: views 366/221/6
# while the rebuilt row said 391/244/7

After

EXISTING=$(gh pr list --head "$BRANCH" --state open ...)
gh pr edit "$EXISTING" --body-file "$BODY_FILE"   # else create
ROW=$(jq -c --arg w "$WEEK" 'select(.week == $w)' ...)

The body reads the measured week's row by its key, because since #4528 an older week can be refreshed in place, so the measured week is not always the last line. A failed edit is an error, not a warning.
