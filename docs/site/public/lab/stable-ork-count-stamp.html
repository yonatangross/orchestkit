Stable ork count stamp no longer rewrites the pin

The marketplace count stamper rewrote the pinned stable ork description with live beta totals. Installers browsing the stable channel saw counts the tag does not ship.

What was broken

origin/main  plugins[0] ork@v9.8.0
  "107 skills ... 171 lifecycle hooks"   <- beta counts

tag v9.8.0    plugin.json / marketplace
  "105 skills ... 218 lifecycle hooks"   <- what the pin ships

stamp_marketplace_json ran whole-file sed /g. Only the pinned entry matched the plugin phrases, so it was the one rewritten. The version stamper already used select(.source.ref == "main") (#3340); the description stamper did not.

What changed

  • stamp_marketplace_json stamps top-level description + tracking entry only (source.ref == "main").
  • Stable description restored to the tag text (105 / 36 / 35 / 218).
  • Channel test asserts pin description equals git show <pin-ref>:..., fetching the tag when CI has none.

Proof (revert)

With the fixed description, the old whole-file sed rewrites stable to beta counts; the new selective stamp leaves it alone:

BEFORE pin:  105 skills / 218 lifecycle hooks
OLD sed:     107 skills / 171 lifecycle hooks   clobbers pin
NEW stamp:   105 skills / 218 lifecycle hooks   pin intact

channel test: pin description == git show v9.8.0:...marketplace.json
  -> fails under the old sed, passes under the new stamp
