Session Category Cascade: Jev at 0.8, haiku below

Every session spawns a detached claude -p --model haiku process to name it and pick one of eight work categories, which becomes the session color. Since #4208 an opt-in typed Choice to TypeSafe's Jev model ran beside it in shadow. This PR does two things the held-out eval (#4210) justified: it ships the eval's criteria as the category definitions for both classifiers, and it turns the shadow into a cascade. Jev decides the color when it is confident; haiku decides otherwise; both outcomes are logged.

Why the criteria, and why 0.8

On 150 held-out sessions with the SAME criteria, Jev and haiku tie (80.0% vs 79.3%, McNemar p=1.0). Both beat the old one-phrase descriptions by about 14 points: the criteria were the variable, not the model. That is why the criteria ship for both paths. Jev's confidence separates the rows it gets right:

Jev confidenceRowsCorrect
below 0.517 6 (35%)
0.5 to below 0.840 27 (68%)
0.8 and above93 87 (93.5%)

The ninth review option from the eval is folded into testing: 10 of 150 rows, under one point of accuracy for either model, and it keeps eight categories and eight colors. Seven of the eight shipped entries are byte-identical to criteria-B.json; testing is the fold.

What runs, and when

turn 1 ─┬─ hash color (instant) ├─ haiku claude -p (unchanged) → session-identity.raw, ~6 to 30 s → title + emoji └─ Jev Choice (opt-in, jev mode) → session-identity.jev.json, 1.1 to 1.7 s confidence >= 0.8 → color set NOW from Jev's category, "category decided by jev" confidence < 0.8 → "category left to haiku: jev said X at confidence Y, below 0.8" error / timeout → "category left to haiku: jev <error>" turn N ── haiku lands → title from haiku; color from Jev if it decided, else from haiku → session-identity.shadow.json + one log line with decided_by=jev|haiku

The number that changed: latency

The eval reported Jev p50 319 ms and p95 399 ms. Those were warm keep-alive calls inside one long-lived process. The hook is a fresh node process per session, so every call pays DNS, TCP and TLS. Measured 2026-09-17, eight cold calls:

node fetch, cold: 1092 1194 1267 1486 1510 1510 1605 1714 ms curl, cold: dns 11 · tcp 239 · tls 482 · first byte 768 ms (server work ~300 ms)

The #4208 abort of 1.5 s would have timed out about half of real sessions and sent them to haiku silently. The budget is now 3 s. The opted-in cost is therefore "the first prompt waits 1.1 to 1.7 s", not "0.3 s".
