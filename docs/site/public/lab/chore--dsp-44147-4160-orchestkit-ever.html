Two Branches, One Line Each

Every playground PR appends exactly one line to a shared generated file, docs/site/lib/generated/lab-data.ts. This page models the fix from issue #4181: a merge=union gitattributes rule plus a deterministic slug sort, so two branches that each add an entry merge cleanly instead of conflicting. Type two slugs and merge them yourself.

1. Two branches off the same base

2. The precondition that makes union safe

A union merge concatenates both sides of a conflicting hunk without markers. That is only safe here because the generator (docs/site/scripts/lab-manifest.mjs) emits one JSON object per line, sorted by slug. Two branches adding entries therefore touch two different lines, and the union keeps both. A multi-line entry would shred; the generator's own check refuses those.

3. The residual risk

Union keeps lines; it never removes them. If an entry was meant to be removed on one branch, a merge with a branch that still carries it leaves a stale aggregate behind. That is why node docs/site/scripts/lab-manifest.mjs --check must stay a required CI gate: it diffs the committed file against a fresh render and fails on any drift, additions or removals.

4. What this PR does not do

It does not gitignore the generated file and it does not move generation into the build. Both are the stronger fix but touch build ordering, which is frozen during the active release. This is the cheap half only.
