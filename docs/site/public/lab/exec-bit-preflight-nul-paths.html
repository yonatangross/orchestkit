The Preflight That Skipped What It Could Not Spell

tests/run-all-tests.sh opens with a read-only exec-bit preflight (#4084): every tracked .sh must be mode 100755 in git and executable on disk, or the run aborts naming the fix. It is fail-closed by design. Issue #4180 found the one input that made it fail open: a non-ASCII path.

Mechanism

core.quotePath defaults to true, so git ls-files -s printed a Hebrew path C-quoted and octal-escaped. The loop read that quoted spelling into $path, and the guard failed, because no file exists under the quoted name. The loop continued, and the file was never mode-checked. The landing spot is what made it invisible: the skip happens on the line whose comment says staged deletion, so a silently-missed file was indistinguishable from an intentional skip, both in the code and in the output.

Before: quoting enumeration 
while IFS=$'\t' read -r meta path; do
    [ -f "$path" ] || continue   # staged deletion: no mode to fix
    ...
done < <(git ls-files -s -- '*.sh' 2>/dev/null || true)

Inside a temp git repo with ascii.sh and בדיקה.sh, both tracked at 100644, git ls-files -s emitted "\327\221\327\223\327\231\327\247\327\224.sh". The guard failed on the quoted spelling and the Hebrew file was never reported.

old preflight block on the fixture: detects 1 of 2

After: NUL-delimited, quoting off 
while IFS= read -r -d '' entry; do
    meta="${entry%%$'\t'*}"; path="${entry#*$'\t'}"
    [ -f "$path" ] || continue   # absent from the worktree: a real absence
    ...
done < <(git -c core.quotePath=false ls-files -s -z -- '*.sh' 2>/dev/null || true)

With -z, ls-files emits raw path bytes and never quotes; the explicit core.quotePath=false documents the intent. The skip comment now states what the skip means: the name on disk is genuinely absent (deleted, or a submodule gitlink), not a spelling artifact.

fixed preflight block on the same fixture: detects 2 of 2

Exposure in this repo today: 0 of 7617 tracked paths are non-ASCII, so nothing was being missed. The fix closes the gate's one fail-open input before the repo ever grows such a path. The space-named file was always detected (a space alone never triggers C-quoting); it is in the fixture to keep that true, pinned by a test.
