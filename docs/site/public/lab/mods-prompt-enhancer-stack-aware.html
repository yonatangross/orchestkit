A 4-word draft should stay a short prompt

Dogfood on 2026-10-22: the draft herdr agents cross harness came back from 0.1.1 as a 30-line essay that invented a repo search, listed four interpretations and asked the user to pick one. 0.2.0 keeps the draft, picks the most likely meaning, names tools the user really has, and ends with one Done when: line.

0.1.1

Investigate how herdr agents work across harnesses in this codebase, and ask me before changing any files.

First, locate herdr. The working directory (`~/scratch`) is not a git repository, so search for herdr under this directory and report the project root, the stack, and the conventions you find. Do not assume a location.

"Cross harness" is ambiguous, so resolve it from the code or ask me. Possible meanings:
1. Running herdr-managed agents under more than one harness (for example Claude Code, Codex, or another CLI runtime).
2. Letting agents in different harnesses hand off work or share state with each other.
3. Defining one shared interface that every harness implements.
4. "Harness" as a test harness, not an agent runtime.

Also confirm whether you should only produce a plan or also implement it.

When the code is read, report in this order:
- Where herdr lives and how agents and harnesses are defined there.
- Which harnesses are already supported, and which are referenced but missing.
- Your two or three best readings of "cross harness", each with the file or symbol that supports it.

If intent is still unclear after reading, stop and ask me which reading to pursue. Do not edit files until I answer.

Once I confirm the goal, the work is done when:
- The change is in place, and you show the command output that proves it. For example, a list command showing agents registered under two or more harnesses, or a test run with its pass count line.
- You paste the file paths you changed and confirm each with `ls` or a read.
- Anything you could not run or confirm is marked as unverified, with the command or location you checked.

0.2.0

Make herdr agents work across harnesses, so Claude Code and other coding-agent harnesses running side by side in herdr panes can be read and sent to from one session. Use the herdr skill for pane reads and sends, and /hq-ext:floor for floor status.
Done when: a message sent from a Claude Code pane reaches an agent in another harness's pane, and its reply is read back in the same session.

Real Haiku 5.5 outputs, recorded with claude -p --model haiku and each version's system prompt (0.2.0 also with the machine's local catalog). The second draft was only run on 0.2.0: גם ןא שךך is do it all typed on a Hebrew keyboard layout.

The catalog

Bundled: OrchestKit's own agents and skills, generated into src/catalog.ts (npm run catalog, checked by a test). Local: npm run catalog:local writes ~/.claude/prompt-enhancer/catalog.md from ~/.claude, the enabled plugins and the MCP server names, plus an optional notes.md. Names and one-line purposes only, sorted the same way every time, capped at 24,000 characters. MCP server commands, args, env and URLs are never read into it.

Why the breakpoint sits in prompt

The mods API docs say a mod that other people run should put its cached static content at the start of prompt: through Bedrock, Vertex, Foundry or a gateway, Claude Code's attribution block fingerprints the start of the user message, so a breakpoint in system can miss. system comes first in the prefix, so the one breakpoint on the catalog block covers both. The cache is shared by every session on the account, so one Enhance warms it for every herdr lane for 5 minutes.
