Five processes per prompt, now three

Every prompt you send runs OrchestKit's UserPromptSubmit hooks, and each registered hook starts its own node process. Before this change there were five. Two of them, prompt/goal-tracker and prompt/worktree-advisory-consumer, were sync hooks with a 5 second timeout. Under load, node's cold start alone used most of that budget. Contributed by @mikemikimike in #4904 (carried as #4909), the fold moves both hooks inside prompt/unified-dispatcher, which already runs on every prompt with a 15 second budget.

The cold-start numbers are the ones measured for this change: about 0.35 s with the machine idle, up to 2.2 s at load1 60 to 86, past 5 s at load1 near 230. The slider interpolates between them, so read it as a shape, not a benchmark. The dispatcher's own hooks run in the same process, so they share one cold start.

What stays the same

The fold keeps both hooks' behaviour. When this session tripped the /goal budget brake, the prompt is still blocked with the same message. A pending worktree advisory still reaches the model and is deleted after delivery, even past the dispatcher's shared context budget. Both hooks stay in the prompt entries map, reached through the dispatcher.
