Stdin path handling after a fetcher pipe

After a fetcher pipe, the interpreter argv walk treats classic stdin names (-, /dev/stdin) as a stdin program. Stdin path aliases are treated like /dev/stdin. An end-of-options marker makes the next token the program. Known benign flags (perl record-separator, node experimental booleans) stay allow when a real script follows.

What the walk does

  1. - and /dev/stdin mean the program is stdin.
  2. Stdin path aliases are treated like /dev/stdin.
  3. After end-of-options: a script path allows; a stdin name denies.
  4. Benign known flags before a real script path stay allow.
