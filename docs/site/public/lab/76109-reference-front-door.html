The Reference tab gets a real front door

Issue #2957. The catalog page at /docs/reference now embeds the skill browser under a "Find a skill" heading, below the three type cards and above the demo gallery. The browser gains two filter groups it never had: Type (Command or Reference) and Complexity.

[0] Try the new filter model

This is a working model of the component change on six real skills. Search, then combine Type and Complexity pills. The behavior matches docs/site/components/skill-browser.tsx.

[1] What changed

reference/index.mdx imports LazySkillBrowser and renders it under a new "Find a skill" heading. The three type cards and the DemoGallery stay.

skill-browser.tsx adds two Orama enum fields (invocable, complexity) and two pill groups. Type maps userInvocable to Command or Reference. Complexity pills list every value the generated data carries, in the atlas order. Each card now also shows a small complexity badge next to the Command badge.

[2] Evidence

vitest __tests__/skill-browser.test.tsx: 28 tests pass, 8 of them new for the Type and Complexity groups. The narrow-page suite still passes. Docs site build is the CI gate.

[3] Scope kept out

Deep reference pages already render breadcrumbs (DocsPage breadcrumb is enabled site wide), so no follow up issue was filed and none was added here.
