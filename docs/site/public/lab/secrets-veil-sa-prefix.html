secrets-veil 0.0.10: a vendor prefix inside a tool name is not a token

The veil matched vendor prefixes as bare strings. The 1Password service-account prefix (o p s _, spaced here) sits inside every hq-ops MCP tool name, so 0.0.9 masked those names from the prefix to the end of the word and the tools never resolved in a seat that loads the veil. The Stripe live prefix did the same to identifiers like a risk_live_status column. In 0.0.10 those two prefixes count only when a real token body follows them: a service-account token is base64 JSON, so it continues eyJ and a long base64url run; a Stripe live key continues with 24+ letters and digits. The shape looks only to the right, so a token right after an escaped \n, \t or %3D is still masked. Every token below is built in the page from split parts; none is real.
