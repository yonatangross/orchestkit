The drift gate named a directory, not the fix

Issue #3507, cost case #3495. 2026-09-14. One workflow step, one added while-loop, exit behavior untouched.

The cost, in one incident

The gate Check for uncommitted build changes fails a PR that edits generated output without rebuilding. Its error named the roster, not the mistake:

::error::Build drift detected! Run 'npm run build' and commit the changes (plugins/ :!plugins/ork/hooks/dist README.md docs/site/lib/generated/ docs/site/public/lab/ plugin.json).

In #3495 an outside contributor edited plugins/ork/skills/api-design/scripts/problem-detail-exceptions.py and had to be told by hand that the source lives at src/skills/api-design/scripts/problem-detail-exceptions.py. A directory list is not a correction. The most common cause of this gate failing, by a wide margin, is editing generated output instead of its source, and the mapping is mechanical:

plugins/ork/skills/<rest>  comes from  src/skills/<rest>

The whole change


Added lines in .github/workflows/ci.yml, inside the drift branch of the step. The original error, the stat, and the exit 1 are untouched; the loop is additive.


git diff --name-only -- "${GENERATED[@]}" | while read -r f; do
  case "$f" in
    plugins/ork/skills/*)
      echo "::error::Did you edit generated output? Source: src/skills/${f#plugins/ork/skills/}" ;;
  esac
done


Properties that did not change: drift still exits 1, a clean tree still exits 0 silently, the roster existence pre-check still runs first, and the hint only fires for paths the diff actually names.


Why no hint for plugins/ork/agents/: #3507 scopes the mapping to skills, where the incident happened and where the roster excludes nothing. Widening the prefix is a one-line follow-up with its own issue.
