prompt-enhancer: listed as a beta, opt-in mod

This PR adds mods/prompt-enhancer to .claude-plugin/marketplace.json as a beta mod, so claude plugin install prompt-enhancer@orchestkit can find it. The mod itself shipped in #4766 and is unchanged. Nothing turns it on: an install does not enable it for anyone who did not ask.

What changes: one marketplace entry (git-subdir mods/prompt-enhancer, ref main, version 0.1.0) and one README line. What does not: the mod code, the ork and ork-alpha entries. Cost: each Enhance is one model call with the haiku alias on the session account, 1024 token cap, 12 second timeout. Needs: Claude Code 2.1.300 or later.

Try the band (simulated, no model call)

This page does not call a model. The rewrite below is a fixed demo transform so you can see the hold, Send and Undo rules. The real mod asks Haiku with the fixed system prompt in src/system.ts.

prompt-enhancer

Enter in the box acts like Claude Code's Enter: a draft ending in ++ is held and enhanced; anything else is sent.

What happened

Rules the band follows

You doThe mod does
Press EnhanceHolds the prompt, puts the rewrite in the box. Never sends during Enhance.
Type a prompt ending in ++, press EnterSame as Enhance. The trigger is removed from the rewrite.
Press Enter on a rewrite that ends in ++ (for example C++)Sends it as is. A rewrite is never enhanced by its own text.
Want to send a typed ++ prompt without a rewritePress Send instead of Enter.
Press UndoPuts back your exact first draft, trigger included. After you edit a rewrite, Undo goes back to your edit.
Edit while the model call runsThat result is cancelled. Your text stays.
The call fails or returns nothingThe original stays in the box and a toast says so.
Slash commands, attachments, prompts from other sourcesPass through without enhancement.

How much model usage would this be

Only clicks cost usage. Loading the mod in a session that never presses Enhance, or never ends a prompt with ++, makes no model call.
