Where CC hides the subagent result

subagent-stopGH-4158CC 2.1.272

Four SubagentStop hooks in OrchestKit (retry-handler, feedback-loop, multi-claude-verifier, auto-spawn-quality) read the subagent's final result from agent_output, falling back to output, summary and result. Measured live on CC 2.1.272, the SubagentStop payload carries none of those keys. The result arrives as last_assistant_message, with the full transcript alongside at agent_transcript_path. On every real payload the old chains evaluated to the empty string, so outcome detection fell through to success and three of the four hooks analysed nothing at all.

This page embeds the same fallback chain the shared reader getSubagentResult() now runs, so you can feed it either payload and watch what the hooks would read.

The reader, verbatim logic


function getSubagentResult(input) {
  const order = ['last_assistant_message', 'agent_output',
                 'output', 'summary', 'result'];
  for (const field of order) {
    const v = input[field];
    if (typeof v === 'string' && v.length > 0) return v;
  }
  return '';
}


Empty strings and non-string values are skipped rather than returned, matching the || chains every call site used, so an empty preferred field exposes a non-empty legacy one instead of masking it.



Why the ghost fields existed at all


The legacy names were documented for SubagentStop early on and stuck in every reader written against the docs rather than the wire. This is the same class measured in GH-3034, where 0 of 11,319 real SubagentStop rows carried agent_output or output. Two consumers were adapted then (unified-dispatcher, subagent-quality-gate); the four above were not, and this change routes all six through the one shared reader in src/hooks/src/lib/subagent-result.ts.
