A broken snapshot is not a win

scripts/perf-compare.sh compares two perf snapshots and exits 1 on a token regression. When a snapshot failed to parse, it used to read as zero tokens, so a truncated after-snapshot looked like a 100% improvement and passed. It now stops with an input error that names the file.

Error: snapshot is not valid JSON: after.json (Expected property name or '}' in JSON at position 1 (line 1 column 2))

Root cause and fix

read_scalars ran JSON.parse with stderr discarded and fell back to echo "0|0|unknown", so any parse failure became a zero-token snapshot. The reader now reports the file and exits 2 when the snapshot is not valid JSON, not an object, or has a token or hook count that is not a non-negative integer. Missing fields still read as 0, as before.

Before fix: 8 failed, 4 passed (tests/unit/test-perf-compare.sh)
