Docs-site drift follow-ups

Two generated files the docs site serves, related-graph.ts (the Related block) and search-suggest-index.ts (search suggestions), had gone stale on main because nothing in CI regenerated them before the drift check. This PR regenerates them and adds the missing CI step, so the next stale copy fails the PR that causes it.

2. The docs-data oracle

The "every skill has valid plugins array" test used to compare against the generator's own output, so a third plugin name could never fail it. It now checks a literal list.

- const validPlugins = PLUGINS.map((p) => p.name);
- expect(validPlugins).toContain("ork");
- expect(validPlugins).toContain("ork-extras");
+ const validPlugins = ["ork", "ork-extras"];
+ expect(PLUGINS.map((p) => p.name).sort()).toEqual([...validPlugins].sort());

3. The new CI drift step

It runs before "Check for uncommitted build changes". Both scripts import only node builtins and repo scripts, so no docs/site install is needed.

- name: Regenerate docs-site link graph and search index
  run: |
    node docs/site/scripts/gen-related-graph.mjs
    node docs/site/scripts/gen-search-suggest-index.mjs

If a stale copy is committed, the drift diff fails and prints this for the two files:

::error::docs/site/lib/generated/related-graph.ts is not written by 'npm run build'.
Run: node docs/site/scripts/gen-related-graph.mjs && node docs/site/scripts/gen-search-suggest-index.mjs
