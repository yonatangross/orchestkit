Consent banner / tap targets

Padding is not a box.

Issue #5186 needed a 44 px hit area on the banner's privacy link. The first pass added py-3.5 -my-3.5: padding reached 44 px, negative margin hid it from the layout. At 390 px the clickable box bled into the consent buttons below it, and a tap near the bottom of the link landed on Allow analytics. The fix is a real box: inline-flex min-h-11 items-center, so the layout reserves the 44 px instead of stealing it from the next row.

Tap near the bottom of the link

Click anywhere inside the banner. The dashed outline marks the link's hit area; the readout says which control actually received the tap.

Both columns use the real DOM: in Before, hit testing inside the dashed area can return a button, because the button sits above the padding. In After, the box reserves its own space, so every tap inside it reaches the link.
