display-lint: right advice for the real shell

The PreToolUse Bash hook that nudges long multi-stage commands into a script file. Three defects, found from a Linux bash host that was told about a zsh trap it does not have.

1. zsh advice on a bash host

Before
SHELL=/bin/bash
... (when the Bash tool shell is zsh, the macOS default,
an unquoted $var never word-splits ...)
After
SHELL=/bin/bash
... A script file renders as one short tool card and
is safe from line-wrap splitting a flag from its
argument: write the steps to ... and run that.

The shell is read the way Claude Code picks it: CLAUDE_CODE_SHELL, then SHELL. The zsh clause appears only when that shell is zsh.

2. Comment lines counted as stages

# step 1: build && test | report; then ship
# step 2: a; b; c
npm run build --workspace=packages/...
Before 8 stages, flagged
After 1 stage, silent

3. A pipeline inside $( ) counted at the top level

VAL=$(git rev-parse HEAD | cut -c1-8 | tr a-z A-Z) && echo "..."
Before 4 stages, flagged
After 2 stages, silent

Unchanged on purpose: real clutter is still flagged, even with a comment or a $( ) in it. case with ;; and one-line for loops still count each statement.
