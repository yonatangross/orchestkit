promote-lights 0.0.16: a dev, qa, main flow finds its promote PR

0.0.15 took one base and one exact head, so a repo with a development into qa PR and a release/vYYYY.MM.DD into main PR could only ever find one of them, and never a release/* head. 0.0.16 reads PROMOTE_BASE as a comma list searched in order, treats a trailing * in PROMOTE_HEAD as a prefix, and reads the required checks from the matched PR's own base (orchestkit#4623).
