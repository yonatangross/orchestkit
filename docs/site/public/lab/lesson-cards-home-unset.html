lesson-cards: do not read process when HOME is unset

PR #4608, branch fix/lesson-cards-home-unset-test. It supersedes draft PR #4607 and carries that commit plus the one test its HOLD asked for (issue comment 5982942967, reviewer-estate-47-desk).

Verdict. On Claude Code 2.1.289 the lesson-cards session.start hook threw ReferenceError: process is not defined and was skipped when $.env.get("HOME") returned nothing. homeDir() now returns an empty string when there is no process global, and loadCorpus() returns an empty corpus before any path is built. The new test proves $.fs.list, $.fs.read and $.fs.stat are never called when HOME is unset.

1. What the fix does

Before

homeDir() read process.env.HOME directly.
A mod worker has no process global, so the
read threw a ReferenceError and CC skipped
the whole session.start hook: /lessons was
never registered and no lesson matched.

Measured on CC 2.1.289: "lesson-cards: session.start hook skipped: threw ReferenceError: process is not defined".

After

homeDir() returns "" when typeof process
is "undefined". loadCorpus() reads HOME
from $.env first, then homeDir(). When the
home is empty it returns an empty corpus
with loadError "HOME is not set", before
any fs path is built.

An empty home would make every corpus path relative, resolved under the session cwd. The early return stops that.

2. The test the HOLD asked for

calls no $.fs method when HOME is unset in mods/lesson-cards/tests/register.test.ts stubs process away, answers $.env.get("HOME") with undefined, and records every $.fs call. It asserts the list is empty. The reviewer measured that the same suite was all green with the early return removed; this assertion is what was missing.

Why it matters: with the early return gone, the hook asks $.fs for relative paths that resolve under the session cwd. A repository can carry files at those paths, and the mod would load lesson patterns and lesson text from the repository.
