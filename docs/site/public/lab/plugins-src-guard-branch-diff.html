plugins-src-guard: a regen may follow its src edit

The pre-commit guard accepted a regenerated plugins/ file only when its src/ file was staged in the same commit. A branch could never commit a regen for src/ edits it made in an earlier commit. The guard now also accepts a src/ file that changed earlier on the branch.

What changed

  • bin/git-hooks/plugins-src-guard.sh: reads an optional list of paths the branch already changed from PLUGINS_SRC_GUARD_BRANCH_FILES. A src/ counterpart in that list counts the same as a staged one. Unset or empty keeps the same-commit rule.
  • bin/git-hooks/pre-commit: fills that list with the paths changed between the merge base with origin/main and HEAD. No merge base (detached, shallow, no origin/main) leaves it empty, which is the strict rule.
  • Probe in a throwaway repo: a src/ edit committed first, then only the plugins/ file staged. With the branch list the guard exits 0; without it, 1.
  • Not changed: the CI Build drift gate still diffs a real build, so a hand edit in plugins/ is still caught there.
