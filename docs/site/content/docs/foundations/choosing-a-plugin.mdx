## Core Plugin, Opt-in Extras

OrchestKit ships its workflows, agents and hooks as one plugin: **ork**. Library and domain reference skills ship separately, in the opt-in **ork-extras** plugin.

Inside a Claude Code session:

```bash
/plugin marketplace add yonatangross/orchestkit
/plugin install ork
```

Or from a terminal:

```bash
claude plugin marketplace add yonatangross/orchestkit && claude plugin install ork@orchestkit
```

No choices, no configuration required. Core `ork` installs <Count k="ork" /> skills, <Count k="agents" /> agents, and <Count k="hooks" /> hooks together. The other <Count k="ork-extras" /> reference skills are in the opt-in [ork-extras](/docs/getting-started/ork-extras) plugin: `/plugin install ork-extras@orchestkit`.

## What Loads When

Not everything runs at once. OrchestKit uses **on-demand loading** to stay fast:

| Component | When It Loads | Overhead |
|-----------|--------------|----------|
| **Hooks** | Session start; only event-matched hooks fire | ~800 tokens/turn max |
| **Agents** | When spawned by name or keyword match | Zero until invoked |
| **Skills** | Injected into agent context when relevant | Zero until matched |
| **Commands** | Available immediately via `/ork:skillname` | Listing only (~80 tokens/skill) |

## Why One Core Plugin

Early versions split functionality into multiple plugins (`orkl`, `ork-creative`). This caused:
- Version conflicts between plugins
- Duplicate hook registrations
- Confusing install instructions

Since v7.0, every agent, hook and workflow skill is consolidated into `ork`. `ork-extras` adds skills only (no agents, hooks or settings), so none of those problems come back. Skills you don't use have zero token cost.
