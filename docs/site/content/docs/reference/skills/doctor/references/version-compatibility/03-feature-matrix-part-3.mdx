**Function hook probes, 2026-09-19** (`claude --version` reports `2.1.277 (Claude Code)`; repeatable end to end via `tests/probes/function-hooks-probe.sh`, four `claude -p` calls with `--model haiku --no-session-persistence`, verdicts grepped out of each run's `--debug-file` log):

```
REFUTED R1-unset user-tier hooks modules not loaded; rollout flag off from the default (a cold GrowthBook cache, no payload yet)
VERIFIED R1-set lesson-cards loaded (tier user); 2 settle lines logged
REFUTED R3-main tool.list hook loaded tier user but never dispatched; Read still offered (model YES)
REFUTED R3-subagent subagent still offered Read and tool.list never dispatched; SUBAGENT:YES
```

Reading: on this account, measured before 2.1.287, a user-tier hooks module (`mods/lesson-cards` via `--plugin-dir`) did NOT load with `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` unset; the debug log names the decider, a cold GrowthBook cache falling back to the compiled default of false, matching the `env ?? GrowthBook ?? false` gate in §2 of the 2026-09-18 cc-mods brief. With the env var set to `1` the same module loads at `tier user` and its `session.start` and `tool.call` hooks dispatch. Re-measured on 2.1.288 (2026-10-03, headless `-p --plugin-dir`, each of the four ork mods, flag unset then set): every module loads and fires with the flag unset, so the env gate applies to 2.1.266 through 2.1.286 only. And `tool.list` is not consulted when the offered tool set is built for either the main loop or an Explore subagent in a `-p` run (zero `tool.list` dispatches in both runs, `Read` still offered in both), so the §6 subtractive-scoping claim does not hold for model-facing tool lists on this build; `tool.describe` (245 settles) is the per-tool surface that actually ran.
