A file on stdin can no longer lose the 100 ms race

Branch fix/run-hook-file-stdin, fixes #4769. Security Tests read passthrough instead of allow for the auto-approve control on a loaded runner.

Same payload, four ways in

stdin100 ms timerverdictwarning

"Timer fires first" is what a loaded runner does: a long synchronous block after the timer is set lets the timers phase run before the read. The test makes it happen every time with a preload that fires that one timer as a microtask.

What changed

  • run-hook.mjs: if fstat(0) says regular file within the 512 KB cap, read it synchronously and run the hook; the timer is never armed for it. Pipes and TTYs keep the timer.
  • The security test keeps the runner's stderr and prints it when a verdict does not match, so the next flake names its cause.
