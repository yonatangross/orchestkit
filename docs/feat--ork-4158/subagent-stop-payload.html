The result was in last_assistant_message all along

Measured live on Claude Code 2.1.272 (GH-4158): the SubagentStop payload carries no agent_output, output, summary or result. The subagent's final message arrives as last_assistant_message. The four SubagentStop consumers chained the legacy names instead, so on every real payload they analysed an empty string: retry suggestions, tried-agent history and the security auto-spawn rules all matched nothing. PR #4232 completes the fix with the shared reader getSubagentResult() wired through all consumers, plus one regression test per hook. Toggle the payload between the measured shape and the legacy shape and watch what each hook sees.

The shared reader

Every consumer goes through getSubagentResult() in src/hooks/src/lib/subagent-result.ts. It prefers last_assistant_message, falls back to the legacy names, then returns ''. Empty strings and non-strings are skipped, so an empty preferred field never masks a non-empty legacy one.

The proof

One test per hook, all feeding a realistic 2.1.272 payload with delete input.agent_output and the result set only on last_assistant_message: retry-handler asserts continue: true with a [PARTIAL RESULT] 25-turn-limit tag; feedback-loop asserts the completed decision written to decision-log.json; multi-claude-verifier and auto-spawn-quality assert the security-auditor rule firing. The reader itself is pinned by __tests__/lib/subagent-result.test.ts, and the reads the payload does not carry (error, exit_code) now carry comments naming the measured key list, so nobody invents a substitute field.
