CI-SENTINEL · #4771

The sentinel model runs only the gh reads it needs

ci-sentinel runs claude -p on every red PR. The model reads untrusted CI logs, and the job token can write PR and issue comments. It ran with --permission-mode acceptEdits and no allow list, so any command ran. Now it runs with dontAsk, an allow list of four gh reads, and a deny list for every gh write form and env read.

AllowDeny (wins over allow)
Bash(gh pr checks *)
Bash(gh pr view *)
Bash(gh run view *)
Bash(gh api repos/*)		 gh api with -X, --method, -f, -F, --field, --raw-field, --input or graphql;
any gh command containing env or ENV
A * in a Claude Code rule matches any text, spaces included, so the allow list alone cannot pin gh api to GET; that is why the deny list exists. No grep, head or jq: they can read files such as /proc/self/environ. Test: tests/ci/test-ci-sentinel-tool-scope.sh. This page simulates the rules with simple wildcard matching.
