memory-lens: the few memories that matter, on every prompt

A new mod in mods/memory-lens. At session start it indexes the project's Claude Code memory files. On each prompt it sends the top 3 matches above a score floor to the model as one context entry, and draws one line for the human. Local files only; no network on the hot path.

Measured on Claude Code 2.1.283: the model receives the context (it named the injected memory in a headless run where it had said NONE before the fix), the line draws in the terminal, and a query takes 2.5 ms at the median and 3.4 ms at p95 over 20 real prompts. Half the memories it shows are useful; it stays quiet on vague follow-ups.

02 / How it hooks in




EventWhat it doesMeasured


session.startFind the project's memory folder (a worktree maps to its parent repo) and build the index in the background.379 files in 309 ms; 2,046 files in 936 ms


prompt.submitQuery before next() and put the context on the event, so it travels down the chain. The first prompt waits for a building index, at most 2 s.An answer built after next() never reached the model: the turn had already started


tool.callRead, Edit, Write, Grep and Glob paths are a new query: at most one memory not yet recalled. A write under the memory folder re-indexes that file.unit tested


command.run/memory-lens stats, reload, show <n>unit tested




Screen line rules found in the TUI: a newline inside one $.ui.log call draws as a replacement glyph, and only the first log call per hook call drew. So the lens draws one line with the memories joined by a bar.

04 / What it never does




no networkno http.fetch, no process.run, no store; remote knowledge arrives only as an optional local mirror file written by something else


no secretssecret-shaped text (key prefixes, PEM headers) reaches neither the screen nor the model


no client titles on screena memory in a clients-* project, or matching a local untracked word list, shows as "client memory (title hidden)"


cappedat most 3 memories and about 600 tokens per prompt
