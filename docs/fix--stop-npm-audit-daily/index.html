npm audit runs once a day, not on every Stop

The stop hook security-scan-aggregator ran npm audit --json every time a session stopped with a dirty working tree. Each run is a round trip to the npm registry, so with many sessions open it added steady CPU and network load. Now the npm audit runs at most once per project per 24 hours. The other scans (pip-audit, semgrep, bandit and the secret scan) still run on every Stop.

The stamp is a file in the temp directory named from a hash of the project path, so each project keeps its own clock. Two new tests put a fake npm first on PATH and count real invocations: a second Stop inside 24 hours runs nothing, and an old stamp lets the audit run again.
