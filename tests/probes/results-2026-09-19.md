## Commands the script ran

R1 arms load `mods/lesson-cards` (a user-tier hooks module via `--plugin-dir`)
and ask for `run: echo hi`; the debug log either shows the module load line
(`hooks module lesson-cards@inline loaded (worker, environment N, tier user);
events: ...`) plus per-event `settled` lines, or the rollout-gate line naming
the deciding source:

```
env -u CLAUDE_CODE_ENABLE_FUNCTION_HOOKS claude --plugin-dir mods/lesson-cards \
  -p "run: echo hi" --model haiku --no-session-persistence --debug-file dbg.log
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --plugin-dir mods/lesson-cards \
  -p "run: echo hi" --model haiku --no-session-persistence --debug-file dbg.log
```

The unset arm uses `env -u`, not an empty assignment: the binary checks the
variable's presence, not its value, so `VAR=` is itself an override that
forces the gate off and would hide the GrowthBook answer.

R3 arms load `tests/probes/tool-list-mod`, a one-file probe mod that answers
`tool.list` with the tool named in `REMOVED_TOOL` (`Read`) filtered out and
writes one marker file per dispatch; the first run asks the main loop whether
`Read` is offered, the second spawns an Explore subagent and asks it:

```
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 TOOL_LIST_PROBE_MARK=<tmp>/mark \
  claude --plugin-dir tests/probes/tool-list-mod \
  -p "<is Read in your tool list? YES or NO>" \
  --model haiku --no-session-persistence --debug-file dbg.log
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 TOOL_LIST_PROBE_MARK=<tmp>/mark \
  claude --plugin-dir tests/probes/tool-list-mod \
  -p "<spawn Explore; ask it the same; reply SUBAGENT:YES|NO>" \
  --model haiku --no-session-persistence --debug-file dbg.log
```

## What was measured

- R1-unset, REFUTED: the debug log carries `installed plugins' hooks modules
  not loaded: rollout flag (tengu_plugin_hooks_modules) is off, from the
  default (a cold GrowthBook cache, no payload yet); built-in plugins load
  regardless`. On this account, tonight, the gate decided off with no env var.
- R1-set, VERIFIED: `hooks module lesson-cards@inline loaded (worker,
  environment 2, tier user); events: session.start,tool.call,ui.render,
  command.register`, then a `session.start` and a `tool.call` settle line.
- R3, both REFUTED: the mod loaded at `tier user` in both runs, but
  `tool.list` was never dispatched in either (zero settle lines, zero marker
  files) while `tool.describe` ran 245 times, `command.describe` 600, and
  `agent.spawn` once for the Explore subagent, which reported `Read` offered.
  On this build a `tool.list` answer is not consulted when the offered tool
  set is built, for the main loop or for a subagent.
