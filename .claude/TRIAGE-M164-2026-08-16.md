## 2. The critical path to beta

**Four issues gate `10.0.0-beta.1`, not 25.**

The gate criterion applied: *does the defect ship inside the plugin artifact and mislead or
degrade a consumer who installs it?* That is the milestone's own thesis ("one correct,
isolated major"). Everything else is a preference, an upstream block, an operator machine
action, or an unstarted feature.

```
#3482  phantom All-tools agent + "1 error during load"   -> ships in artifact

#3477  container ships node 22 while engines demand 24   -> ships as a release artifact
```

**Blocking relations: there are none. All four are mutually independent and can land in
parallel.** No one of them cannot start until another lands. Stating that plainly matters,
because the milestone's shape invites the assumption of a dependency chain and there isn't
one here.

- #3322 cannot proceed until an OS sandbox actually loads.
- #3424's Phase 1 soak already failed and was rolled back with `gh` broken estate-wide.

So the chain is blocked on an **operator decision about a machine**, not on any code this
repo can merge. It should not be allowed to hold the beta.

## 3. Charter violations

The governing rule: *CC mechanism is the SUBSTRATE, our need is a LAYER on it via CC
extension points. EXTEND is default. OVERRIDE and DIVERGE are banned.*

**Violation 1 (#3311 and #3322, as originally written): OVERRIDE of a scope that does not exist.**
Both prescribe arming `sandbox.enabled` from `src/settings/ork.settings.json`. A plugin's
`settings.json` is not a settings scope: CC reads only `agent` and `subagentStatusLine` from
it and `.strip()`s the rest with no diagnostic. Shipping the key there is not extending CC,
it is asserting a scope CC does not honour, which is why #3345 "armed" nothing and #3357
correctly deleted the block rather than adding the key. Already self-corrected on the issues;
flagged here because the **titles still prescribe the banned fix** and will mislead the next
reader.

**Violation 2 (#3424, as specced): OVERRIDE that provably fights the substrate.**
The rollback evidence is the charter argument in miniature. Enabling the sandbox with ork's
carve-out list applied to live sessions immediately, broke `gh` across the estate, and locked
Bash out of the very file needed to undo it. A layer that can disable the operator's ability
to remove the layer is not extending the mechanism. Any retry must start from CC's own
`excludedCommands` (with `gh` in it from minute one) rather than an ork-authored carve-out set.

**Violation 3 (#1273): DIVERGE risk.**
Consolidating 42 `.claude/<namespace>` paths into 5 means ork imposing its own layout inside
CC's own config directory. That is only EXTEND if the chosen namespaces are ones CC sanctions
for plugin use; otherwise it is ork homesteading CC's directory and will break the next time
CC claims a name. The re-scope should state which namespaces are CC-sanctioned before any
sweep is designed.

**Correctly resolved, recorded so they are not re-litigated:**

- **#2528**, the tempting fix (gitignore `plugins/`) was rejected as unsound because a
  marketplace install expects the built tree committed. That is the charter reasoning applied
  correctly; the duplication stays until CC ships namespaced skill discovery.
- **#3311's `permissions` block**, deliberately retained after being proven inert, on the
  stated ground that "the key was inert" must not silently become "the risk was reviewed".
  That is the right call and worth preserving through any later cleanup.

**Not a violation, contrary to appearance:** #3326. Keeping build-time Phase 5 *alongside* the
CC `dependencies` array is not a parallel mechanism, the two guard different pipeline points
(source integrity at build vs dependency satisfaction at install). The two-track proposal is
EXTEND, not KEEP-by-inertia.

## 5. Definition-of-done risk

The milestone's merge bar is: *every fix carries a test that FAILED before it and PASSES
after, with the failing output recorded in the PR.* This is where the milestone will stall,
so the `SHIP-IN-V10` set is graded against it explicitly.

**Can meet the bar cleanly (all four beta gates):**

| # | The failing test |
|---|---|
| 3477 | Assert `Dockerfile` `FROM node:<major>` equals `.nvmrc` major and satisfies `package.json` engines. Fails today (22 vs 24), passes after. Cheap and permanent. |
| 3461 | Assert no `src/agents/*.md` declares a key CC ignores for plugin agents. Fails today on 36, passes after. The `hooks:` half already proved the pattern via #3494. |
| 3482 | Assert every entry under a component dir is a valid component (agent has frontmatter, skill dir has SKILL.md). Fails today on exactly 2, passes after. This is also the doctor check the issue asks for, so the test and the feature are the same artifact. |
| 3483 | Assert the cleanup hook's target path resolves to an existing, installed channel dir. Fails today (`orchestkit/ork` does not exist), passes after. **Guard against the fixture trap the charter names**: the test must resolve the real channel, not a fixture that mirrors the bug. That is precisely the "103 passing tests on dead code" failure the milestone was founded on. |

**Cannot meet the bar. Highest stall risk:**

- **#3311 / #3322 / #3424 (the whole security chain).** The change is to
  `~/.claude/settings.json`, outside the repo. No PR here can carry a before/after test,
  because no PR here makes the change. #3424 additionally has an *anti*-test: the one
  execution produced a rollback, so the honest artifact is a documented failed soak, not a
  passing test. **These three should not be held to the same bar, and saying so explicitly is
  better than letting them sit open failing a criterion they structurally cannot meet.**
- **#3190.** Structurally impossible. A test that failed before requires the failure to
  occur; 48 trials produce zero hangs on the byte-identical binary. There is nothing to make
  go from red to green.
- **#3263.** The failing path (`SKILL.md:253`) cannot be triggered on demand, and that is the
  open question, not a known behaviour. The DoD-shaped work here is the measurement
  experiment, and it should be scoped as an experiment with a recorded result, not as a fix
  with a test.
- **#3326.** The prerequisite is a live trace against the installed CC binary to establish
  what the `dependencies` array actually does on 2.1.228. That is a probe artifact, the same
  evidence class #3457/#3458 set, not a unit test.
- **#3448.** Reproducing it requires provoking the harness into auto-backgrounding a
  foreground Bash call on timeout, which is nondeterministic and harness-version-coupled.

**Partial:** #3353 piece 1 can carry a test (assert the resolver is gone and the catch-all
